# 全球城市印章目录与动态字号实施计划

## 摘要

完善城市印章的动态排版，并接入可分区浏览的全球城市目录。以联合国《World Urbanization Prospects 2025》的城市口径作为目录边界，保留每个城市的中英文名、国家/地区、项目内序号及稳定 ID；港澳台名称按“中国台湾、中国香港、中国澳门”表达。城市可以浏览和预览，但只有已保存日记地点与城市名称精确匹配时才允许应用印章。

## 当前状态分析

- `src/components/library/city-stamp.tsx` 中目前只有京都、镰仓、台南三条配置；`CityStamp` 用 `cityName.length` 在 14 和 17 两档之间选择字号，不能确保长名称不超出印章。
- 素材库 `app/library/index.tsx` 直接遍历 `cityStampOptions` 展示全部印章；明信片 `app/postcard/index.tsx` 通过 `getCityStampConfig(decorationId)` 查找配置。目录扩充后不能继续把约一万多枚 SVG 全部铺在素材库页面。
- 现有日记模型 `DiaryItem.location` 是自由文本，没有城市目录 ID。示例地点包含城市名和附加地点（例如“台南 · 安平”），因此用精确的地点分段匹配比任意子串匹配更符合“去过才解锁”的要求。
- 现有稳定装饰 ID 为 `stampKyoto`、`stampKamakura`、`stamp`。新目录需保留这些 ID 的兼容映射，且既有明信片装饰不能因解锁状态变化而无法读取。
- 联合国 WUP 2025 使用“人口至少 50,000、人口密度至少每平方公里 1,500 人”的城市定义。GeoNames 提供多语言备用地名，并按 CC BY 4.0 授权，需保留来源署名；其中文别名需要校验，不能不经审核直接视为准确。用户已确认接受 ODbL；因此允许以 OpenStreetMap 城市/城镇中英文标签补充中文名，但必须执行精确名称、坐标唯一匹配、贡献者署名及目录数据库 ODbL-1.0 发布边界。

## 已确认的决策

- 城市目录范围采用联合国 WUP 2025 城市定义，不声称覆盖所有规模的城镇或聚居点。
- 数据以 WUP 2025 的城市及国家/地区条目为基准；城市英文名及城市集合以该数据集为准，中文名优先使用 GeoNames 中文别名并做重复、归属和名称质量校验。无可靠中文名的条目必须进入人工核对清单，不以英文原文冒充中文名，也不静默漏掉。
- 城市序号是产品内展示编号，不代表官方排名；在每个国家/地区分组内按城市中文名拼音排序，从 `01` 开始，固定写入目录数据。
- OSM 派生城市名称纳入时，随包目录数据库依 ODbL-1.0 发布，并在城市目录页显示 OpenStreetMap 贡献者署名及许可入口；此许可边界不扩展至 App 源代码。
- 港澳台地区名称在中文数据中分别标为“中国香港”“中国澳门”“中国台湾”；印章英文地区名分别显示 `HONG KONG · CHINA`、`MACAO · CHINA`、`TAIWAN · CHINA`。对应内部地区键使用不易混淆的稳定值，不以裸 `TW` 作为显示归属。
- 素材库增加按国家/地区分区浏览入口，目录中的所有城市均可查看并预览印章；应用按钮仅对已解锁城市开放。
- 解锁只依赖用户已保存的真实日记地点，不使用测试/演示数据、草稿或生成中任务作为到访证据。地点经空白、大小写和分隔符规范化后，只有某个地点片段与城市中文名、英文名或经审核别名完整相等时才解锁；模糊包含不解锁。若同名城市不能唯一归属，则需地点中包含足够的国家/地区信息，否则保持锁定。
- 新增目录记录使用稳定、确定性的城市 ID；保留现有三个装饰 ID 的解析兼容。锁定只限制新应用动作，不阻止解析并显示已经保存的旧装饰 ID。

## 拟议修改

### 数据目录与生成/校验工具

- 新增 `src/data/city-stamp-catalog.json`，作为 App 随包发布的规范化目录，包含目录版本、来源标识，以及每个城市的稳定 ID、中文名、英文名、国家/地区键与中英文显示名、展示序号、经审核的匹配别名。
- 新增 `tools/city-stamps/` 下的数据构建与校验脚本，以及其 README。脚本读取 WUP 2025 与 GeoNames 来源文件，按稳定地理标识匹配城市，按展示国家/地区和中文拼音排序后生成目录；校验每个条目的必填字段、稳定 ID 唯一性、序号连续性、地区归属、港澳台命名、重复城市及缺失中文名，并输出待人工核对清单。
- 在工具说明中记录 WUP/GeoNames 的数据版本、下载地址、处理规则和授权署名要求。只将规范化后的运行时目录打包进 App，不将庞大的原始 GeoNames 全量别名表加载到运行时。

### 目录查询与城市印章

- 新增 `src/components/library/city-stamp-catalog.ts`，提供国家/地区分组、分区城市查询、按 ID 查询、稳定旧 ID 兼容、城市地点匹配和解锁状态计算。查询保持轻量，支持在用户选择国家/地区后只渲染该分区的城市，不一次性生成全部 SVG。
- 更新 `src/components/library/city-stamp.tsx`，把目录字段与 SVG 绘制参数分开，并用纯函数根据城市中文名实际字符类别、字形宽度估算和 SVG 可用安全宽度计算字号；字号在可读范围内动态缩小。若极长名称在最小字号下仍超宽，使用不拆分字符的省略显示，保证任何城市都不会溢出印面。
- 固定 SVG 的城市文字安全宽度、最大/最小字号和字符宽度规则；顶部编号和底部地区英文分别使用目录中的字段，不从城市名称临时拼接或推断。
- 保持 `CityStamp` 可继续接受旧 `CityStampConfig`，或通过兼容转换函数读取新目录项，避免破坏明信片和既有测试调用。

### 分区浏览与应用门禁

- 更新 `app/library/index.tsx`，保留当前印章入口的原有版式边界，新增“按国家/地区浏览”入口；避免在主页面一次性渲染完整目录。
- 新增 `app/library/cities.tsx`，按国家/地区分组浏览城市，显示中文名、英文名、地区及两位序号；选择城市后进入现有印章预览样式。允许锁定城市预览，明确展示锁定态和未满足条件的说明。
- 在城市预览中，解锁项可继续执行“用于明信片”；未解锁项禁用该应用操作。地点匹配仅使用真实已保存日记的 `location` 字段，按明确的分隔符拆分和标准化后对城市名/审核别名做完整匹配；多个同名候选无法唯一对应时不解锁。
- 更新 `app/postcard/index.tsx` 的目录解析，支持新城市 ID，同时继续解析 `stampKyoto`、`stampKamakura`、`stamp` 三个旧 ID。

### 测试与项目文档

- 新增目录查询、地区分组、ID 稳定性、别名匹配、同名城市歧义、缺字段/重复序号及港澳台命名的单元测试。
- 为字号计算新增边界测试，覆盖单字、常见城市名、长中文名、混合字形、最大/最小字号和省略回退；素材库/明信片组件测试继续验证旧 ID 映射与新 ID 渲染。
- 更新 `app/__tests__/library-screen-decorations.spec.tsx` 和 `app/__tests__/postcard-screen-assets.spec.tsx`，验证分区浏览、锁定城市可预览不可应用、地点精确匹配解锁、没有真实到访记录不解锁以及旧装饰仍可显示。
- 按项目交付规则更新 `docs/reference/delivery/tasks/MAT-003.md`、`docs/reference/delivery/test-cases/MAT-003.md`、`docs/reference/business-spec/modules/material-library.md` 和 `docs/reference/delivery/reports/development-progress.md`；保留既有验收证据，不把目录预览误记为真实明信片图片导出通过。

## 验收标准

- 每个目录条目均有非空中文名、英文名、国家/地区归属、稳定 ID 和分区内唯一的两位序号；目录校验报告中无未处理的缺失、冲突或政策命名问题。
- 城市中文字在印章的安全宽度范围内；短名称不会被不必要地缩小，长名称会按可用宽度缩小，极长名称按规则省略且不溢出。
- 用户可以按国家/地区分区浏览并预览目录城市；未到访城市不能应用，满足精确匹配的城市可以应用。
- “台南 · 安平”可凭完整地点片段“台南”命中对应城市；仅靠模糊子串、无关草稿、测试数据或存在归属歧义的同名地点不能解锁。
- 港澳台地区名称和印章英文标签符合已确认规范；京都、镰仓、台南现有 ID 仍能被明信片页解析并显示。
- 本期验收的是素材库选择和明信片页面 SVG 预览；不将当前尚未实现的明信片实际图片导出认定为通过。

## 验证步骤

1. 运行目录构建/校验工具，确认来源版本、总条目数、缺失中文名清单、重复项、序号连续性和港澳台归属映射。
2. 运行新建的目录/字号定向测试，以及 `app/__tests__/library-screen-decorations.spec.tsx`、`app/__tests__/postcard-screen-assets.spec.tsx`。
3. 运行 `npm run typecheck` 和相关格式/差异检查。
4. 在 iOS 模拟器检查城市分区浏览、预览、锁定/解锁状态、不同长度中文名的印章排版，以及旧 ID 的明信片展示；模拟器目视检查作为 SVG 字体度量估算的补充，不以测试 mock 代替。
5. 按项目交付策略集中整理测试发现的问题，在下一轮修复并更新任务台账；不以目录数据本身推断用户已经到访。
