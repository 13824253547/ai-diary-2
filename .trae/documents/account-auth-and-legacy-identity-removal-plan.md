# 账号认证与匿名身份移除计划

## 摘要

将当前以安装密钥、App Attest 和 `deviceId` 为基础的匿名身份体系，替换为用户名/密码账号认证。注册和登录均通过自建拼图验证码；必须登录后才能进入应用；一个账号只允许一个有效登录会话。提供独立的退出登录和永久注销操作。

新账号从空数据开始，不认领或迁入旧匿名身份数据。切换时立即清除旧身份关联的服务端记录、媒体文件，以及本机旧匿名草稿和缓存。永久注销同样清除账号关联数据。允许同一账号在不同时间使用不同设备登录，但新登录会撤销此前会话。

本计划是实施方案，不代表已执行数据迁移。旧云端记录和文件的清理不可逆；开发阶段只在受保护的隔离 E2E 数据库验证。任何生产数据库或生产文件目录的清理都必须在实施时再次确认目标后单独执行。

## 当前状态分析

- `app/_layout.tsx` 启动时调用 `ensureDeviceIdentity()`，随后恢复草稿和回忆；当前没有认证门禁。
- `src/services/device-identity.ts` 同时包含旧设备 ID、App Attest 以及安装级 Ed25519 身份流程；`src/services/installation-identity.ts` 将安装私钥和令牌存入 Keychain。
- 多个前端 repository adapter 通过 `getDeviceIdentityHeaders()` 注入设备身份。
- `backend/src/modules/identity/identity.module.ts` 注册了全局 `IdentityAuthGuard`；业务请求依赖 bearer token 和匹配的 `x-device-id`。
- `backend/prisma/schema.prisma` 中多类日记、照片、聊天、记忆、成长和发现数据通过 `ownerDeviceId` 隔离；照片文件也由后端资产服务管理。尚无账号表、登录页面、登出或账号永久注销能力。
- `app/(tabs)/profile.tsx` 是现有“我的”页面入口，当前仅显示匿名个人页与隐私政策。
- `docs/reference/delivery/decision-register.md` 的 Q-012 和安装级身份契约记录了此前“不新增账号登录”的决定。以用户本次确认的新范围为准，实施时需标注旧决定被取代，保留历史验收证据。
- 当前工作区有 `src/config/app-config.ts` 未提交修改，包含应用名称“橙光AI日记”和对应描述。后续若移除该文件中的设备认证配置，必须保留这些现有用户修改。
- 已核对 CRE-002 的任务、CASE 和设备身份照片链路。本次不调整照片选择交互及其已记录证据；素材归属字段随账号数据归属一起迁移。

## 已确认的产品决策

- 登录标识：用户名和密码；用户名为 4–32 位 ASCII 字母、数字或下划线，大小写不敏感。
- 不绑定邮箱或手机号，不提供自助密码找回；注册界面必须明确告知忘记密码后无法自行恢复。
- 拼图验证码由项目自建，注册和登录都必须验证；服务端签发一次性挑战并校验答案。
- 所有主要功能必须先登录，不保留匿名访客模式。
- 同一账号只允许一个活跃会话；后续登录会撤销之前的会话。
- 退出登录只结束当前会话；永久注销另设入口，需要再次确认，并删除该账号及关联服务端数据。
- 旧匿名数据不迁入账号。身份切换时立即删除旧匿名身份的云端记录、公开内容及媒体文件，同时清除本机旧匿名草稿与应用缓存。iOS 系统相册中的原始照片不属于应用私有数据，不删除。
- 不修改与认证无关的业务页面、流程和样式。

- 新增 `docs/reference/delivery/tasks/BAS-005.md` 与 `docs/reference/delivery/test-cases/BAS-005.md`：将账号、身份替换、旧数据清理及账号删除列为独立可追踪范围。
- 更新 `docs/reference/delivery/decision-register.md` 的 Q-012，说明本次决策及生效边界；不删除或伪造历史记录。
- 按仓库约定更新 `docs/reference/delivery/coverage.md`、验收矩阵及 `docs/reference/delivery/reports/development-progress.md`，开发状态与 CASE 验收状态分别记录。
- 更新隐私政策与上架材料，准确披露用户名/密码、账号关联数据、账号删除入口和实际保留/备份边界；不承诺代码或服务商无法保证的数据删除范围。

### 后端认证、会话和防机器人

- 在 `backend/prisma/schema.prisma` 增加账号、活跃会话、一次性拼图挑战及必要的限流记录模型；使用独立 Prisma migration。
- 新增 `backend/src/modules/auth/`，实现验证码签发/校验、注册、登录、会话撤销、退出登录和永久注销 API。用户名在服务端规范化并唯一约束；密码仅以带随机盐的 Argon2id 哈希保存，明文不得进入日志。
- 拼图挑战使用后端现有 `sharp` 能力生成带缺口背景和独立拼图块；客户端使用现有 `react-native-svg`/React Native 组件展示及拖动。挑战与注册或登录用途绑定，短时过期、单次消费；答案只由服务端校验，客户端不能自报通过。校验失败可重新获取挑战。
- 对 IP、用户名摘要及挑战签发/验证/密码失败实施服务端限流；认证失败响应避免泄露用户名是否存在。验证码是防滥用的一层，不作为唯一防护。
- 新登录原子撤销该账号此前的会话，再创建新会话。业务 JWT 绑定 `userId` 和 `sessionId`，每次请求检查会话有效状态；访问令牌不能替代数据库中的撤销检查。
- 退出登录撤销当前会话；永久注销要求有效密码和独立确认，先撤下公开内容，再级联清除账号数据、媒体文件和会话。对于数据库事务与文件系统不具备共同事务的问题，采用可重试、幂等的清理阶段，失败时保留可审计状态，不向客户端谎报完成。
- 用新的账号认证守卫替换 `backend/src/modules/identity/identity-auth.guard.ts` 注册的全局设备身份守卫；删除业务请求对 `x-device-id` 的依赖，不采集硬件指纹。IP 限流只用于短期防滥用，不作为用户身份或数据归属。
- 对后端 API、Store/repository adapters 及上传/SSE 请求做全量身份传递替换：将设备归属改为认证后的账号 ID，并确保客户端不可提交或覆盖该 ID。
- 盘点并移除 `backend/src/modules/identity/` 中 App Attest、安装密钥、设备令牌及设备挑战代码；移除不再使用的 Prisma 模型、iOS App Attest entitlement 与客户端原生依赖。仅删除确认没有其他调用方的依赖。

### 数据归属与旧匿名数据清理

- 将 `backend/prisma/schema.prisma` 中业务数据的 `ownerDeviceId` 归属改为账号归属，覆盖日记、素材、照片配额/副本、锚点/纠正、聊天、成长报告/里程碑、草稿/任务/幂等命令、发现内容和点赞等实际存在的字段。
- 为旧匿名数据清理建立受保护的一次性操作：先输出各表记录数、身份数和媒体路径的 dry-run 清单；执行需显式确认参数并验证数据库目标。清理范围包含匿名私密/公开内容、用户生成媒体、任务和身份挑战记录。
- 生产清理不得通过普通启动流程或 Jest 隐式触发。自动化仅对 `backend/test/e2e-database-safety.ts` 保护的隔离数据库执行，并强制注入 `E2E_DATABASE_URL`；开发库和生产库禁止用于清理测试。
- 迁移切换时不把本机旧快照绑定到新账号；首次进入账号体系时清除旧设备身份命名空间的应用私有草稿快照与缓存。不得删除系统相册原图。
- 永久注销账号时同时清除其所有数据库行与后端媒体资产，包括素材原图、副本、日记、聊天、记忆、成长数据、任务和公开发现快照；公开故事须先撤下。第三方服务日志和备份按其已核实的实际保留策略处理并披露。

### 客户端登录门禁与账号操作

- 新增 `app/auth/login.tsx`、`app/auth/register.tsx` 和对应的 `src/services/`、`src/contracts/`、`src/repositories/` 认证实现；登录/注册页提供拼图验证、加载/错误状态和重新获取挑战入口。
- 在 `app/_layout.tsx` 恢复并校验账号会话后才加载账号数据；无会话或已撤销会话时仅进入登录/注册路由。不得回退到匿名身份或展示上一账号的缓存。
- 在 `src/services/api-client.ts` 的认证头工厂中提供账号令牌；替换所有 `getDeviceIdentityHeaders()` 使用点。图片上传继续沿用项目要求的原生 XHR 传输，PET SSE 请求也使用相同账号会话头。
- 在 `app/(tabs)/profile.tsx` 增加当前用户名、退出登录和永久注销入口。退出时撤销当前服务器会话、清除安全存储凭证及内存中的账号数据；账号切换时按新账号命名空间加载，绝不复用其他账号缓存。
- 永久注销需再次输入密码并明确确认不可恢复；处理期间锁定重复提交，成功后清空本机该账号缓存并返回登录页，失败时保留必要会话以便重试。
- 只新增完成登录、注册、拼图验证、账号展示、退出和永久注销所需的界面；不顺带调整其他页面 UI/UX。

## 假设与约束

- 本次计划获批后，用户名登录和单活跃会话为唯一身份路径；App Attest 与安装 Ed25519 身份不保留为并行用户身份或降级认证。
- 账号数据按 `userId` 隔离；由于每账号仅一台设备可同时活跃，不设计多设备并行访问。
- 计划默认密码长度为 8–128 个字符；后端使用 Argon2id，并按服务端资源确定哈希参数。
- 不提供找回密码或客服重置密码流程；注册前需明显告知账户无法自助恢复的风险。
- 旧匿名远端数据和本地匿名草稿均按已确认决定清除，不提供认领、合并、导出或过渡保留期。
- 生产数据库/媒体目录的不可逆清理仍需执行阶段再次核实精确目标；未核实前不得执行生产迁移、删除、部署或清空操作。
- 继续遵守 CRE-002 及现有素材注册/设备照片规则；所有后端隔离集成测试遵守 E2E 数据库保护要求。
- 保留当前未提交的 `src/config/app-config.ts` 应用名称与描述修改；移除身份配置时逐段合并，不覆盖其他用户改动。

## 验证与验收

- 后端定向测试：用户名规范化/重名竞争、Argon2id 密码验证、错误响应不枚举账号、验证码过期/错误/用途不符/重放拒绝、限流、单活跃会话撤销、登出失效、注销幂等及媒体清理失败恢复。
- 客户端定向测试：必须登录的路由门禁、注册/登录验证码重试、认证失败状态、令牌安全存储、会话被撤销、登出及注销后的缓存隔离；验证旧匿名快照不会进入新账号。
- 隔离 MySQL E2E：账号 A 无法读取/改写账号 B 的日记、素材、聊天、锚点、成长记录或任务；新登录撤销旧会话；永久注销撤下公开内容并删除相关数据/文件。所有 E2E 强制经 `backend/test/e2e-database-safety.ts` 与 `E2E_DATABASE_URL` 保护。
- 迁移测试：在一次性旧 schema 数据库上验证 dry-run 计数、匿名记录/媒体清理、schema migration 与空账号注册；确认任何失败都不会把测试指向开发库或生产库。
- 静态检查：全仓业务请求不再发送或依赖 `x-device-id`；正式运行路径不再调用 App Attest 或安装私钥注册；Expo 配置及最终 iOS entitlement 不再声明 App Attest；所有账号归属均由服务端认证主体确定。
- 运行前端 `npm run typecheck`、认证相关 Jest；运行 `npm --prefix backend run build` 与相关 Jest；隔离 MySQL E2E 单独记录。因原生模块/entitlement 变更，最终按项目规则构建并启动 iOS 模拟器；另需真实 iPhone 验收拼图拖动、注册、登录、会话互斥、退出及永久注销。
- 不因替身测试或模拟器成功宣称生产验证码抗绕过、生产数据清理、邮件找回（本范围不提供）或真实发布环境已验收。
