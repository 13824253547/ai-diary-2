# 实施与测试共同约定

日期：2026-10-13。本文只集中记录跨任务约定；具体工作和验收见每项任务及同名测试文件。

## 项目背景

这是 iOS 优先的 Expo Router / React Native / TypeScript 应用，使用 Zustand 管理内存状态。目前日记、照片、发现、成长主要来自 `src/mocks`；生成、聊天、导出、平台分享存在本地模拟。当前仓库未提供生产后端、真实 AI 适配、持久化仓库或完整集成测试环境。

产品范围来自[业务规格](../business-spec/README.md)、[通用规则](../business-spec/common-rules.md)和[用户流程](../business-spec/user-journeys.md)。真实交付必须读取真实用户数据、产生可使用结果，并完成相应持久化或外部交付；提示“成功”、固定回复和开发页切换状态不证明交付完成。

## 编号与追踪

- 功能沿用 `CRE-001` 等 FSD 编号；任务为 `T-CRE-001`，文件为 `tasks/CRE-001.md`。
- 任务验收为 `T-CRE-001-A01`；案例为 `CASE-CRE-001-001`，文件为 `test-cases/CRE-001.md`。这与旧 RTM 的 `TC-*` 用例种子分开，避免改变旧编号含义。
- 原始 AC → 任务验收 → CASE → 测试代码与执行证据。测试文件写明具体任务验收 ID；任务写明原始 AC，补充工程验收明确属于本次实施要求。
- 全部任务初始为“未开始”，全部案例初始为“未执行”。有未确认规则的案例单独标“待决策”，不得当成已通过或直接生成空的跳过测试。

## 执行边界

先完成 [BAS-001](tasks/BAS-001.md) 中与当前任务有关的决策与接口；不要求无关业务问题全部关闭才开始工作。技术选型可由实施者基于仓库提出并记录；商业范围、公开内容、成长规则等产品决策不得从 mock 数字推断。

每项任务的“依赖”是完整验收前需具备的能力；纯函数、界面和契约测试可先用明确的测试替身开发。与该任务无关的登录界面、付费、评论发布、关注、日记删除不自动加入范围。后台访问身份与数据隔离由 BAS-002 解决，不等同于新增账号产品。

数据/API、错误码、请求标识和取消语义在 BAS-001 交付的契约中确定；任务使用业务对象和行为引用契约，不凭空绑定尚不存在的文件、数据库或服务商。AI 供应商、运行时模型与开发代码所用模型是独立选择。

## 测试环境与证据

1. 确定性测试：可控时钟、ID、存储与服务替身；验证规则、请求、状态、失败及竞态，不能替代真实集成。
2. 真实集成：iOS 测试设备、隔离测试数据、实际相册/文件/AI/后端或平台 SDK；记录环境、契约版本、输入、结果与请求/文件证据。外部条件缺失时报告阻塞。
3. AI 质量：固定评测输入和经确认的质量维度；结构、照片归属和状态用自动断言，内容质量按评测表执行，不逐字匹配 mock 正文。
4. 执行报告逐条填写 `CASE ID | 任务验收 ID | 环境/版本 | 通过/失败/阻塞/未执行 | 测试代码位置 | 证据 | 缺陷/复测`。文档评审案例保留人工检查性质。

现有 [15 个领域场景](../../../tools/diary-domain.test.ts)及[运行器](../../../tools/run-domain-tests.js)作为回归资产迁移和补充；其历史通过结论只适用于原测试覆盖。不得删除失败断言来让真实实现“通过”。
