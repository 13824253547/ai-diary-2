# T-SHR-005 真实平台交付与长图/PDF导出

状态：**进行中**。业务依据：[隐私与分享 · SHR-005](../../business-spec/modules/sharing-and-privacy.md#shr-005-平台分享长图与-pdf)；原始验收：`SHR-005-AC01`, `SHR-005-AC02`, `SHR-005-AC03`, `SHR-005-AC04`。

## 实施范围

- 替换 `recordShareDemo` 先记成功的演示动作。建立准备、交付、取消、失败等真实操作结果，具体终态与记录事件依 BAS-001/Q-014 契约；预览准备不能代表文件保存或平台发布。
- 真实渲染长图/PDF并写入已决定的系统/文件出口，返回可读取实际文件；私密允许本地导出，选段与匿名内容沿用统一投影，匿名输出不得携带未遮挡原图。
- 只实现页面已表达的朋友圈、小红书、X 出口；通过正式支持的系统/平台适配器交付真实资产。私密在任何外部调用前拦截并提供公开范围入口。
- 分别保存平台行为与导出行为，按约定事件更新且渠道去重；请求绑定目标、内容版本及出口，防止重复/乱序结果写错作品。权限拒绝、写失败、不支持/未安装、取消等按真实结果反馈，原日记不被导出动作修改。

## 当前进展

- `app/share/result.tsx` 目前仍停留在 `recordShareDemo(...)` 的演示路径，正式页面尚未接入真实系统分享或文件导出，这部分现状已与任务定义明确区分，暂不把演示反馈记作真实交付。
- 本轮已新增 `src/services/share-delivery-orchestrator.ts`，先把不依赖正式前端改动的真实交付规则收口到服务层：
  - 私密作品点击外部渠道（朋友圈、小红书、X）时，会在任何资源准备或渠道适配器调用前被拦截，不会误记平台成功记录。
  - 所有分享/导出动作都会先依赖 `prepareShareAssetsForDiary(...)` 准备当前投影对应的图片资产；匿名与选段规则沿用 `SHR-002 / SHR-003 / SHR-004` 的现有真实投影与匿名资产能力。
  - 只有在导出文件或外部渠道返回“已确认完成”的结果后，才会通过 `onConfirmed(...)` 回写平台/导出记录；取消、失败、权限拒绝、环境不支持都不会被误记为成功。
  - 操作作用域已按 `diaryId + version + mode` 收口；同一作品同一版本同一出口的重复提交会复用在途操作，不同版本或不同出口则各自独立，避免乱序结果串写到错误作品或错误内容版本。
- 本轮继续新增 `src/services/share-export-file-service.ts`，并把它接到 `share-delivery-orchestrator` 的默认本地导出分支：
  - `save` 现会生成真实 PNG 文件；当前先采用“已准备图片拼贴 + 结构化内容骨架”的服务层拼版输出，不再停留在“只提示成功、不写文件”的演示状态。
  - `pdf` 现会生成使用 `STSong-Light` / `UniGB-UCS2-H` 的 CJK Type0 字体映射 PDF，不需在应用中捆绑字体资源；2026-10-15 的 macOS Quick Look 实际预览已确认中文标题、正文与匿名标记可读。当前仍缺 iOS 实际打开/跨阅读器验证与 Q-014 最终版式规格，故 A02 保持 partial。
  - 输出文件路径已按 `diaryId + version + operationId + mode` 隔离，不会覆盖其他作品或其他内容版本，也不会改写原日记、原图或分享投影。
- `createShareExportFileService(...)` 现允许注入文件 writer；服务单测以 fault plan 注入写盘异常并验证返回 `delivery_failed`。编排层回归使用同一真实文件服务边界，确认失败时不触发 `onConfirmed(...)`，也不改日记的导出历史。该证据覆盖确定性写失败，不代表 iOS 系统权限或真实设备磁盘故障已通过。
- `src/store/create-app-store.ts` 本轮继续把“确认后才记记录”的约束落到领域层：新增 `confirmShareDelivery(...)`，只在 `operationId + diaryId + version + mode` 四元组匹配时写回平台/导出记录；同一操作 ID 的重复确认只记一次，旧版本或错目标的晚到回调会被直接拒绝，不再把外部回调误写到当前作品或当前内容版本。
