**状态：进行中（DEV-3 已建持久会话 API/client repository，待集中测试；正式页面未接线）。** 关联 [FSD PET-001](../../business-spec/modules/companion.md#pet-001-小橘聊天)，原验收 PET-001-AC01～AC04；[同名案例](../test-cases/PET-001.md)。

## 任务内容

- 将关键词即时回复替换为真实陪伴生成能力和会话仓库。发送用户消息、请求回复、保存会话与重开加载均读取同一用户的真实记录；欢迎语可以是产品引导，不能代替已发送消息。
- 定义消息 ID、角色、顺序、请求状态与请求标识在 UI 和服务之间的映射。发送中、失败及重试在页面给出可观察状态；重复点击、响应丢失和乱序回复不得生成重复消息或把旧回复接在错误会话之后。
- 保留空白拦截、去空白、角色气泡、滚动定位及可用平台的键盘行为。输入长度和 AI 质量、时限、安全边界从 Q-002、Q-003 落地，不沿用 mock 关键词为产品规则。
- 对本机退出 / 重开及身份切换验证会话归属和留存；真实集成以隔离账号和真实服务响应为证据。

## DEV-1 实施进度

- `src/services/chat-reply-provider.ts` 新增可注入的 `ChatReplyProvider` 契约，输入包含 `conversationId`、稳定 `requestId`、尝试序号和规范化文本；输出明确标记 `mock` / `provider` 来源及可选 provider request ID。Store 会对运行时结果执行非空正文、来源标记和 request ID 类型校验，畸形响应 fail closed；provider 异常只存固定 `provider_failed`，不把原始响应/异常正文写进 issue log。
- 原有关键词回复内容移入 `createMockChatReplyProvider()`，只在 `appConfig.mode === 'hybrid-dev'` 时默认注入；其他模式缺真实 provider 时由 fail-closed adapter 返回失败，不会以 mock 伪装成功。
- `src/store/create-app-store.ts` 为聊天 turn 保存会话/请求关联和 pending/completed/failed/stale 状态；异步结果按原用户消息位置插入，重复回包不再追加第二条助手消息。失败请求的 `retryChat(requestId)` 沿用业务 request ID 并递增 attempt，旧 attempt 的迟到结果会被丢弃。
- `src/types/diary.ts` 为消息增加可选关联元数据，现有气泡、角色、页面文案、按钮、滚动及输入路径均未修改；同步 mock 保持现有回复和即时呈现。
- **尚未完成：** 当前只支持一个内存中的活动会话；Q-001 决定的会话留存/重开/身份切换尚未实现。异步失败目前只记 Store request 状态与 issue log，现有页面没有失败/重试可见接线；Q-002 的质量、安全、超时/取消/重试策略未确认。上述缺口不计为完成。
- **测试状态：** PET-001 CASE 均未执行；本轮未新增/运行聊天测试。前端 `npm run typecheck` 与 backend `npm run build` 均通过。为解决 backend Node 工程默认加载 DOM 与 Node 全局类型冲突，`backend/tsconfig.json` 显式限定 `lib: ["es2021"]`。此编译检查不代表 CASE 通过；把 frontend store 直接导入 backend e2e 的实验用例已撤下，留待集中测试阶段设计隔离 runner。

## DEV-3 会话、消息与请求持久服务

- 新增 `ChatConversation`、`ChatTurn`、`ChatMessage` Prisma 模型与 `20261016001000_pet_chat_sessions` migration 文件，均未应用到数据库。消息使用 turn sequence 固定排序；每个 turn 记录 owner device、request ID、请求指纹、attempt、用户/助手消息 ID、状态及固定失败码。
- 新增 `GET /chat/conversations`、`GET /chat/conversations/:conversationId`、创建用户 turn、完成回复、记录失败和显式重试 API。所有路由要求 `x-device-id`；设备不匹配 fail closed。同请求同内容重放不重复创建消息，不同内容复用 request ID 会拒绝；回复只接受当前 attempt，完成结果重放不会覆盖原回复；失败不保存 provider 原始异常；由于当前没有可信服务端聊天 provider，`NODE_ENV=production` 在创建/重试/回复写入前 fail closed，历史仍可读取。所有非测试运行环境还会拒绝调用方自报 `source: provider`，但允许明确标记的开发 mock 回复。
- 新增 `pet-chat-v1` contract、HTTP repository 和 backend adapter，并加入 `AppStoreAdapters`。回复仍由既有 `ChatReplyProvider` 生成，`hybrid-dev` mock 来源继续显式标注；持久服务不硬编码回复，也不将存储失败转成 mock 成功。测试环境以外的 `source: provider` 是不可信调用端声明，不代表真实 provider 已配置或质量已验收。
- `src/store/create-app-store.ts` 的 chat/image/report 默认 mock 现同时要求 `appConfig.mode === 'hybrid-dev'` 和开发运行时；release 下 `__DEV__ === false` 时使用 fail-closed provider。Jest 可使用其隔离的显式 mock。此修正避免 `mode` 常量本身让 mock 进入 release bundle 的运行路径。
- 正式宠物聊天页与 Store send/retry 流程尚未调用该 repository。接线会让成功等待/失败恢复进入真实网络路径，而页面没有失败/重试可见状态；在 UI/UX 边界未授权前暂停该入口接线，继续保留服务层开发。旧的本地 mock 呈现不被称为服务持久化完成。
- Q-001 的保留期限、清理/删除及跨设备恢复仍未确认；migration 未应用，不建立用户侧留存承诺。Q-002 未决定质量/安全/超时和自动重试策略；Q-003 未决定输入长度与键盘矩阵。实现只提供显式失败和调用方控制的 attempt，不推断重试次数或间隔。
- 新增 `chat-sessions.controller.spec.ts`、`chat-sessions.service.spec.ts`、`http-pet-chat-repository.spec.ts` 与 `pet-chat-contract.spec.ts`，均已编写未运行。客户端 contract validator 现拒绝孤立/错序消息、turn 状态与助手消息不一致、失败缺少固定码、用户消息携带回复来源及空白消息体；completed turn 的助手 ID、来源和 provider request ID 必须与对应回复一致。HTTP repository 也会在网络请求前拒绝未知失败码。前端 `npm run typecheck` 与 backend build 通过；没有应用 migration、运行 Jest/e2e 或调用外部模型。
- 会话列表 query 现只接受单一十进制整数文本；指数、十六进制、小数、空白填充及重复 `page/pageSize` 均在 controller 返回 `invalid_input`，且设备身份仍先校验。service 对运行时分页对象、数值类型、安全整数、页码范围和页容量再次校验，非法值不触发 Prisma。新增 controller/service regression 已编写，未运行，留待集中 TEST。
