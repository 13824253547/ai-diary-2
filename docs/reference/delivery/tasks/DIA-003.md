## 任务内容

- 复用真实照片选择和资源校验，将全篇集合、封面、段落/图片块、人物及海报引用作为一次草稿原子更新；保留 normalizeDiaryPhotos 的关系规则。
- 段落引用确认时合并全篇集合并更新关联图片块；取消只丢弃选择暂存。不能从 mock 全量数组接受未知或不可读资源。
- 并发替换、请求失败和存储重试按草稿版本处理，防止旧集合覆盖新选择；提交由 DIA-005 负责，新建生成失效规则与 CRE-005 一致。

## 任务验收

- **T-DIA-003-A01：**映射 **DIA-003-AC01**。确认全篇替换后集合等于选择，封面及引用全部在集合内。
- **T-DIA-003-A02：**映射 **DIA-003-AC02**。段落引用照片同时存在于全篇集合和目标正文/引用块。
- **T-DIA-003-A03：**映射 **DIA-003-AC03**。替换引用同步关联图片块为新首图；清空则移除其关联图片块。
- **T-DIA-003-A04：**映射 **DIA-003-AC04**。被移除照片不再被封面、段落图片、人物或海报引用。
- **T-DIA-003-A05：**映射 **DIA-003-AC05**。重复选择不产生重复引用，无效 ID 不入草稿。
- **T-DIA-003-A06：**【工程新增】取消/失败不部分提交引用；并发旧响应不可覆盖新集合，保存后从仓库读取仍满足引用不变量。

## 当前实现与证据

- `src/store/create-app-store.ts` 已落地 `setDraftBlockPhotos(...)` 的原子更新：段落引用确认时会先过滤未知照片 ID，再把引用集合并入整篇 `selectedPhotoIds`，同步更新人物分组，并把关联的独立图片块首图改成新的第一张；若新引用为空，则会直接移除该关联图片块。
- `src/store/diary-domain.ts` 已通过 `normalizeDiaryPhotos(...)` 保证整篇照片集合、封面、海报、段落引用、独立图片块和人物头像始终收敛在同一合法集合内；被整篇移除的照片不会继续残留在封面、独立图片块或人物信息里。
- `src/store/__tests__/diary-domain.spec.ts` 本轮已补 `DIA-003` 的领域证据：整篇换图后集合/封面/海报/段落引用/人物都会被规范化；段落引用换图会把新照片并入整篇集合，并同步把关联图片块切到新的首图；保存后重读的 `diary-1` 仍保持最新合法集合且不会生成重复作品。
- `app/__tests__/album-select-screen.spec.tsx` 已覆盖编辑态整篇换图的页面链路：替换模式会把新集合写回同一草稿并返回编辑页，旧请求不会覆盖新结果，取消也不会提交未确认集合；换图后旧生成结果会失效，保存时需重新生成。
- `app/__tests__/edit-screen.spec.tsx` 本轮又补齐了段落引用面板的页面级注入证据：当已有引用在确认时被判定为不可读，或可读性校验直接失败时，编辑页都会阻断提交并显示中文提示；关闭面板也不会把暂存选择写回草稿，满足 A05/A06 对“失败/取消不部分提交”的要求。
- 当前剩余未收口部分仅剩 Q-003 / Q-008 / Q-001 对应的上限、既有换图下限/重生成和留存规则，也就是 `CASE-DIA-003-009` 的待决策边界。
