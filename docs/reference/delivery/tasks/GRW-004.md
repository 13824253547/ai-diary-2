## 任务内容

- 用真实锚点 ID 与来源版本保存用户理解，替换拼接标签 / 日记 ID 的内存字典。纠正初值读取已提交内容或提取结果，底部入口定位第一条当前可用锚点。
- 非空、去空白及输入限制从统一校验执行；写入确认前显示处理中，失败不标记成功、不清掉待保存输入，可重试；关闭 / 取消未提交修改不写入仓库。
- 保存不改原日记正文；按 Q-016 定义标签范围及向提取、聊天、报告的传播，并保留能区分提取结果与用户纠正的来源信息。并发纠正 / 原文变更按 BAS 契约处理，不能静默旧写覆盖。
- 重开与身份切换验证纠正留存、权限及更新标识，读写不能跨用户复用。

## DEV-3 版本化纠正 repository/API

- 新增 `docs/reference/delivery/contracts/anchor-correction-v1.md`，定义按设备、日记、来源版本与锚点寻址的纠正读取/写入契约；不改变正文，也不决定跨标签、聊天或报告传播。
- 后端新增 `AnchorCorrection` 与 `AnchorCorrectionCommand` Prisma 模型及 migration 文件（尚未应用）。纠正值按 `ownerDeviceId + diaryId + anchorId + sourceDiaryVersion` 唯一定位；服务验证日记归属、当前版本、成功 provider extraction 中的真实 anchor ID 及其 text/quote 来源块，并用 `expectedVersion` compare-and-update、设备作用域幂等命令在同一事务写入。
- 新增 `GET/PUT /anchors/:anchorId/correction`，缺少 `x-device-id` 会 fail closed；空白纠正拒绝；读写事务先锁来源日记行再校验版本，来源日记或纠正版次冲突不会覆盖。契约和服务不设置 Q-003 未确认的产品字数上限。
- 幂等命令重放核对其记录的 `correctionVersion`：若纠正已被后续命令更新，旧键返回 `version_conflict`，不把当前新值冒充旧命令结果，也不另存历史纠正文副本扩展 Q-001 未确认的敏感文本留存。
- 前端新增纠正 contract、HTTP repository 和 backend adapter，并纳入 `AppStoreAdapters`；正式页面没有读取/写入该 repository，旧的内存纠正 UI 行为未改变。API 已将 anchor ID 绑定到 GRW-003 持久成功提取记录；页面/store 接线、留存和真实来源质量仍未闭环，因此不能宣称端到端纠正已完成。
- Q-001 留存期限/恢复范围、Q-003 字符边界、Q-016 原文变化后的纠正同步及下游传播保持待确认。数据库 migration、单元/集成 CASE、客户端请求和重开留存尚未执行；本实现待集中 TEST。纠正读写会拒绝没有对应持久 provider anchor 的任意 ID。
- DEV-3 本轮新增 superseded command 重放回归，尚未运行；`npm run typecheck`、`npm --prefix backend run build`、`git diff --check` 通过。未应用 migration、未连接数据库、未接正式页面。
- DEV-3 输入/响应 guard：纠正读取的 `diaryVersion` query 只接受单一十进制文本，controller/service/repository 均拒绝 malformed 请求对象；repository 校验返回记录的 diary/version/anchor 与读取目标一致，保存响应还绑定 source block、规范化纠正文本和预期递增版本。新增 controller/service/client regression 未运行，不改变幂等或冲突规则。

## TEST-12 / DEV-11 / TEST-13 migration 实证

- TEST-12 的全量 Prisma migration fresh-deploy 在 `AnchorCorrection` 唯一索引处发现默认索引标识超过 MySQL 64 字符限制。DEV-11 于 Prisma schema 与 migration SQL 同步映射为 `AnchorCorrection_owner_diary_anchor_version_key`，唯一字段仍为设备、日记、锚点和来源版本；缺陷修复轮计 `1/2`。
- TEST-13 在新的隔离 MySQL schema 上 6/6 migrations 部署成功，`migrate status` up-to-date、schema diff 无 drift。该环境不含用户数据，且已在测试后清理。
- 此结果只验证当前 Prisma schema/migration 可部署；未创建真实 provider 锚点、未验证服务归属/来源写入，也未接正式页面。CASE-GRW-004-001～009 保持原状态，真实 Q-001/Q-003/Q-016 前置仍未闭环。
