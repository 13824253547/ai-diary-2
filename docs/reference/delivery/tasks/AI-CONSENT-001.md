# AI-CONSENT-001 首次AI授权提醒

日期：2026-10-29。状态：前端提醒及入口检查已实现，定向测试通过；真实iOS与生产环境验收待完成。

本任务为用户新增范围，不改变原42项任务、225条验收或原有通过统计。

## 已确认范围

- 首次生成日记前说明所选照片用于AI创作，以及保存后整理该篇文字记忆和成长线索。
- 首次发送聊天前说明聊天文字、会话上下文、近期日记摘要，以及完成问答的文字记忆整理。
- 首次生成配图前说明场景描述；首次全库成长识别或洞察前说明已有有效日记正文的分析范围。
- 系统原生弹窗提供“暂不使用”和“同意并继续”。不默认同意，不在App启动时统一弹出；每种用途独立授权。

## 实现

- `src/services/ai-consent.ts`：按设备身份、服务地址和授权版本读取并保存各用途的同意时间。串行弹窗与写入，防止重复点击、用途相互覆盖。拒绝/关闭不记录同意；存储失败提示并不继续处理。身份、服务或版本变化后重新提醒。
- `src/hooks/use-ai-consent.ts`：授权等待期间防重，离开或关闭页面可取消等待，不执行晚到的处理回调。
- 日记生成页在`startGeneration`之前授权，不在同意前上传照片或轮询新任务。等待时显示确认授权，阶段最短展示时间从实际生成开始计算；已完成任务的阅读不重启生成。
- 更换排版师的重新生成、编辑页重写与保存同样检查日记用途，避免提前调用或旧日记首次保存后的后台整理绕过提醒。
- 萌宠发送及失败重试检查聊天授权；授权期间禁止重复发送，输入/会话变化后不提交旧文本。灵感卡直接发送入口共用聊天授权，仅发送用户实际回答，不拼入引导问题。
- 配图在`generateMaterialImage`之前授权，拒绝保留描述。关闭或取消面板使旧提交版本失效，晚到授权/生成结果不覆盖新请求。
- 花朵首次全库初始化和报告首次生成、重试共用全库用途。只读成长状态不作为模型调用；未授权时明确说明并提供重新授权动作，不虚报分析中。授权拒绝不删除既有日记或成功报告。

涉及页面：`app/create/generating.tsx`、`app/create/character.tsx`、`app/diary/[id]/edit.tsx`、`app/(tabs)/pet.tsx`、`app/library/index.tsx`、`app/profile/flowers.tsx`、`app/profile/report.tsx`。

## 真实性与实施边界

- 授权弹窗只说明AI处理及用途范围，不声明模型归属或服务商。源码仍保留Ark provider适配器；实际接收方应以生产配置和数据流核验为准，不能从弹窗文案推断模型已迁移。
- 授权记录保存在当前设备的应用文件中，不跨设备共享；本轮不是后端集中同意台账，也未新增服务端签名同意验证。
- 用户这次授权的是前端首次提醒与相关页面入口检查。本轮没有新增设置页撤回开关、设备数据删除、正式政策链接、服务器级任务撤销或全部后台任务强制授权机制，不以此宣称完整隐私合规完成。
- 已经运行的历史服务端任务或外部直接调用不受本次前端弹窗控制。生产仍需补齐服务端授权审计和任务处理控制；现有自动整理用途在首次提醒中明确告知。
- 不新增原生依赖、不改照片至少3张规则、素材容量、正文布局、聊天模型提示词或用户既有改动，不调用计费模型、不操作真实用户数据库。
