# T-PCD-002 明信片真实分享与图片保存

状态：**开发接线完成，真实设备与目标 App 验收待执行**。业务依据：[明信片 · PCD-002](../../business-spec/modules/postcards.md#pcd-002-明信片分享与保存)；原始验收：`PCD-002-AC01`, `PCD-002-AC02`, `PCD-002-AC03`。

## 实施范围

- “分享给好友”可直接进入当前卡片的渠道选择；若未提前生成，复用 PCD-001 准备真实资产，并在完成前不允许交付不存在/旧版本文件。
- 提供已表达的微信好友、朋友圈、保存图片出口；前两者将当前可读资产交给已确定平台适配器，后者真实写入已确定系统出口并能独立打开。
- 渠道取消/关闭只结束该动作，保留照片、贴纸、城市印章与当前完整卡片选择；区分准备、实际交付、保存、取消和错误，不宣称已发布/已收取。
- 处理权限拒绝、生成/写文件失败、未安装/不支持平台和重复回调；操作与输入版本绑定，不能把旧卡交付为当前卡。明信片是否遵循日记私密/匿名必须按 Q-013 决定，不自动沿用或绕过。

## 依赖

[BAS-001](BAS-001.md)（Q-013/Q-014 出口契约）、[BAS-003](BAS-003.md)（文件生命周期）、[BAS-004](BAS-004.md)、[PCD-001](PCD-001.md)（真实当前卡片）；可复用 [SHR-005](SHR-005.md) 的平台/保存适配器，不能直接套用其未决隐私规则。依赖用于完整验收，接口与纯规则可先使用明确的测试替身。共同约定见[执行上下文](../execution-context.md)。

## 决策与阻塞范围

- [Q-014](../../business-spec/open-questions.md)：阻塞正式支持渠道/系统保存许可、输出规格与结果回调语义；确认后进行设备交付验收，不假设一定能获知第三方发布成功。

- Q-015/Q-001：阻塞作品/文件留存；本任务不自动新建分享历史业务。

## 2026-10-27 局部决议及实现

- 用户确认系统分享面板代替定向微信/朋友圈适配器；已安装小红书/X 等仅在其分享扩展支持图片时由系统列出，不保证 App 内发布。私密或匿名来源原图明信片经用户主动触发允许外发；无需自动脱敏。
- 直接点击“分享明信片”或“保存到相册”时，从当前可读卡片生成临时 PNG；分享前确认系统分享可用，保存请求相册只写权限。取消或平台不支持不计分享成功，权限拒绝或渲染失败不伪报保存成功；导出期间禁止重复提交，输入变化后丢弃旧结果。
- 页面和导出服务已有定向自动化，尚未在重建原生开发包后验证系统分享面板、小红书/X 扩展、相册独立打开和 SVG 印章在 PNG 中的完整视觉；完整 CASE 暂不标通过。

## 2026-10-27 组合卡片导出

- PCD-001 的当前卡片由照片、可选贴纸和可选城市印章共同组成；分享与保存捕获同一个完整卡片视图。任一素材 ID 或照片 URI 改变均使输入版本变化，旧捕获不能用于新组合。
- 本地页面替身验证不代替真实系统分享、相册独立打开或 SVG/图片叠层的设备验收；PCD-002 CASE 状态不因本地组合测试扩大。
