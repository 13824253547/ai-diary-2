## 任务内容

- 用真实互动服务保存每个可访问故事的当前用户点赞状态，显示服务认可的计数；列表与详情读取同一故事状态，不靠基础 mock 数字加本机布尔值作为最终计数。
- 处理重复点击、响应丢失、乱序确认和多设备并发；按 BAS-001 的请求标识 / 版本契约保证一次目标状态只有一个生效结果，不出现负数、重复点赞或跨故事串状态。
- 点赞失败时反馈并恢复或重试到可确认状态；撤回 / 不可见故事不得继续产生可见互动。重开应用后按身份恢复已点赞状态。

## DEV-1 源码盘点

- 列表/详情点赞现以 `likedDiscoveryIds` 本地数组切换图标，并在静态 `discoveryItems.likes` 上加减；没有服务端唯一关系、幂等请求、真实计数、跨页面远端刷新或重启留存。
- 后端身份头与 Prisma/MySQL 基础可复用，但故事发布/可见性、匿名身份、撤回后点赞和并发计数规则受 Q-007；跨设备/离线范围受 Q-001。未据本地布尔状态宣称真实互动完成。
- 本轮未改页面/Store点赞行为或运行 DSC-003 CASE；自有互动服务可在权限/发布边界确认后继续实现。

## DEV-2 后端实现

- 新增 `PUT /api/discovery/stories/:storyId/like`，使用目标状态 `liked: boolean`，通过 `(storyId, ownerDeviceId)` 复合主键和 upsert/delete 实现可重放写入；响应返回服务端计数与当前设备状态。
- 仅对显式发布、未撤回且 `likesEnabled=true` 的快照写入；该标记默认关闭，没有发布写入 API。Q-007 对点赞资格/撤回互动的产品规则未确认，服务不会自行开放。
- 禁用点赞时 service 返回 `interaction_not_available`；controller 以 HTTP 409 保留该领域错误，client repository 识别并传递结构化错误，不把“故事不允许点赞”误报为输入格式错误。该错误映射不改变 Q-007 下的点赞资格或启用规则。
- 原有 controller/service 测试在 TEST-4 的 backend 8 suites / 77 tests 中通过，backend build 通过；DEV-3 新增的 controller 错误映射及 client repository 断言尚未运行。列表/详情页面仍使用既有 Store，未接入该 API；migration 未应用，未执行多设备 MySQL 竞争与完整 DSC-003 CASE。
