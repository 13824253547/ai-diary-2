## 任务内容

- 使用真实生成/识别的人物候选及照片关系，替代 mock personIds 推导；命名保存仍只修改当前草稿人物元数据。
- 将名称输入计量、长度/空值和默认回落纳入契约；当前 maxLength=16 仅原型边界，不作为未确认正式上限。
- 保存/跳过处理版本、重复操作和存储失败，失败保留已输入内容；不自行增加跨日记人物档案或改写已生成正文。

## 任务验收

- **T-CRE-006-A01：**映射 **CRE-006-AC01**。真实人物候选存在时进入命名，无候选直接进入编辑。
- **T-CRE-006-A02：**映射 **CRE-006-AC02**。各候选可分别编辑称呼，输入边界按 Q-003 确认执行。
- **T-CRE-006-A03：**映射 **CRE-006-AC03**。保存更新当前草稿人物信息及别名，正文逐块保持原值。
- **T-CRE-006-A04：**映射 **CRE-006-AC04**。跳过进入编辑且保留人物，不要求跨作品复用。
- **T-CRE-006-A05：**映射 **CRE-006-AC05**。提交作品时空自己/同行者称呼分别回落为“我”/“同行人”；边界按 Q-003。
- **T-CRE-006-A06：**【工程新增】无效人物、重复提交和写失败不丢失其他人物输入，不把失败当保存成功。

## 当前进展

- 已完成 `T-CRE-006-A01`：
  - `backend/src/common/diary-generation.service.ts` 已去除 deterministic provider 在“无候选”场景下伪造 `person-self` 的兜底。
  - `src/store/diary-domain.ts` 已改为仅消费生成结果内的 `people`，不会再从旧草稿回退人物候选。
  - `src/store/create-app-store.ts` 已在生成完成时同步 `draft.people` 与 `draft.diary.people`，避免命名页/编辑页分流读取旧候选。
- 已完成 `T-CRE-006-A03` / `T-CRE-006-A04` / `T-CRE-006-A05`：
  - `src/store/create-app-store.ts` 中 `setDraftPersonName(...)` 继续只更新当前草稿人物元数据与别名，不改写正文块；提交保存时空自己/同行者称呼会分别回落为“我”/“同行人”。
  - `app/companion/naming.tsx` 已将“保存名字”改为真实保存步骤，保存成功后进入编辑；“跳过，以后再说”会保留当前人物与照片关系，直接进入编辑。
- 已完成 `T-CRE-006-A06`：
  - `src/store/create-app-store.ts` 新增 `finalizeDraftPeopleNaming(...)`，本地命名保存失败会保留输入并返回失败结果。
  - `app/companion/naming.tsx` 已加入页面级防重入锁，连续点击保存只会触发一次保存。
  - 无效人物 ID 的更新会被忽略，不会污染其他人物输入。
- `T-CRE-006-A02` 当前仅完成“各候选可分别编辑称呼”的部分；正式长度/字符计量仍受 `Q-003` 限制，当前 `maxLength=16` 仅沿用原型边界，不能当正式规则闭环。
  - `app/companion/naming.tsx` 已将多同行者输入框的可访问标签收口为唯一值：单同行者保持“同行人的名字”，多同行者则改为“第 1/2 位同行人的名字”，避免真实多候选场景下输入框撞名，也让各候选独立输入的页面证据可稳定落地。
