# T-MAT-001 真实照片导入、搜索与预览

状态：**进行中**。业务依据：[素材与灵感 · MAT-001](../../business-spec/modules/material-library.md#mat-001-照片素材添加搜索与预览)；原始验收：`MAT-001-AC01`, `MAT-001-AC02`, `MAT-001-AC03`。

## 实施范围

- 将示例照片选择替换为真实设备照片导入；选定符合 Expo/iOS 环境的照片适配器，按系统许可读取用户选中照片。当前依赖不代表已有可用上传/导入实现。
- 建立素材资产仓库与共享解析接口：稳定资产 ID、可读取 URI/资源、媒体类型/尺寸、标题、时间/地点及来源；让素材、日记照片组件和明信片读取同一真实资产，而非只在 `mockPhotos` 查 ID。
- 同一已识别照片再次导入只复用已有素材；导入成功须真实可读且仓库提交成功。处理许可拒绝/撤回、用户取消、失效 URI、损坏图片、写入失败，不创建伪成功条目。
- 按标题/地点片段查询素材；预览对应资产并能关闭。使用状态以当前已保存日记引用为依据，未保存草稿不提前改成已用于日记；提交后刷新。批量上限与元数据缺省由 Q-003 确定。

- Q-003：阻塞格式/尺寸/数量上限与时间地点缺失预期；Q-018：共享 CRE-001 的全量/有限/拒绝/撤回许可决策适用于本任务设备导入。

## 当前进展

- `src/store/create-app-store.ts` 已把照片目录从外部依赖数组改为每个 store 自己的状态；`registerPhotos(...)` 现在以不可变方式合并稳定 ID，并复制照片对象及 `personIds/faceRects` 子数组，避免注册设备资产时改写全局 mock 数组、保留调用方可变引用或污染其他 store。
- `addMaterialPhoto(...)` 现会按当前 store 已注册的照片目录校验资产，并对相同 ID 去重。领域测试证明一个已注册的设备照片可进入当前会话素材成员集合，未知 ID 不会加入，第二个 store 不会看到第一个 store 的设备资产。
- `T-MAT-001-A02` 的素材搜索页面回归已通过：标题与地点片段均只返回匹配项，无匹配显示空态，清除查询恢复原素材集合。素材页现在从 store 注册的照片目录解析成员 ID，支持非 mock 资产及本地 URI 缩略图；搜索回归使用已注册的非 mock 设备照片 fixture。
- `T-MAT-001-A03` 已部分验证：非 mock URI fixture 可从素材列表打开预览并在关闭后回到列表；“未生成日记”标记只在当前已保存作品未引用该照片时显示，store 中已保存引用更新后页面标记会同步变化。测试未读取真实设备文件或执行完整导入/保存链路，因此 A03 不标通过。
- `app/postcard/index.tsx` 与日记 `Photo` 组件现均从统一照片目录读取注册素材；本地 URI 资产可传递到两个消费者，明信片切换回模板时仍遵循原有行为。正式页面布局与交互未改变。
- `CASE-MAT-001-006` 已有部分跨模块证据：素材库、日记照片组件、明信片三个消费者均以非 mock `source: 'device'` file URI fixture 读取同一资产目录；这不证明真实导入和 URI 可读性。
- 以上不等同真实导入完成：`app/library/index.tsx` 的添加照片入口仍是示例照片选择；真实设备选取、URI 可读性和持久化仍未完成。
- 已验证：`npx jest --runInBand app/__tests__/library-screen-search.spec.tsx app/__tests__/postcard-screen-assets.spec.tsx src/components/diary/__tests__/photo.spec.tsx`（3 suites / 8 项通过）、`npm run test:domain`（3 个套件/87 项通过）、`npm test -- --silent`（39 suites / 302 项通过）、`npm run typecheck`。已有 store 资产注册隔离用例亦验证重复 ID 不增加素材成员。
- 完整导入仍受 Q-015 的资产身份/URI 生命周期、Q-018 的权限矩阵和当前正式 UI/UX 不变约束影响，相关阻塞见 `autonomous-blockers.md`。
