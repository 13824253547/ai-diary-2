# T-BAS-003 业务数据与照片资产持久化

状态：进行中。草稿、生成任务、保存命令及已保存日记已接入 Prisma/MySQL；日记正文快照与元数据在同一事务持久化，未提交草稿支持同设备本地恢复。Prisma 现有初始 schema 与 `Diary.contentSnapshot` 演进迁移；独立 MySQL 验证覆盖空库部署、旧版记录升级和受控 baseline adoption。本地 `ai_diary` 已在 schema diff 无漂移后完成 migration baseline，2 条既有日记记录数保持不变，migration status 为 up-to-date；legacy 日记正文回填、数据库损坏恢复仍待实现。素材资产生命周期、其余业务对象留存及按 Q-001/015 确认的完整重启范围也未完成。依赖：[BAS-001](BAS-001.md) 的 Q-001/015 与存储契约；远程模式另依赖 [BAS-002](BAS-002.md)。关联：BR-01/02/05/11、Q-001；[实施约定](../execution-context.md)。

## 任务内容

1. 建立持久化仓库，保存已提交日记、公开设置、素材照片、聊天、点赞、锚点纠正和成长结果；未提交草稿按确认的恢复策略保存。
2. 将照片从数字资源编号扩展为真实可读取的资产引用，保存稳定 ID、URI/远程引用、时间地点及人物标记；导入和配图不能只依赖临时缓存。
3. 启动加载与 Zustand 初始化协调；未加载完成不把空列表写回覆盖历史。生产空账户从真实空数据开始，mock 仅用于显式演示或测试。
4. 日记保存、草稿完成标记及关联对象按契约原子提交；写失败保留可恢复草稿，不显示保存成功。
5. 处理 schema 版本迁移、损坏记录和媒体失效；不静默清空用户数据。按确认方案落实本地/远程同步、冲突和留存。
