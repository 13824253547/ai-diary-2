# T-PCD-001 当前素材的真实明信片生成

状态：**进行中（已接入临时 PNG 捕获，设备验收待完成）**。业务依据：[明信片 · PCD-001](../../business-spec/modules/postcards.md#pcd-001-选择素材与生成明信片)；原始验收：`PCD-001-AC01`, `PCD-001-AC02`, `PCD-001-AC03`。

## 实施范围

- 从统一素材资产仓库选择一张真实可读照片；不绘制照片日期/时间水印，仅在地点有效时显示地点标记。可选加入一张贴纸和一个已解锁城市印章，通过稳定 ID 读取。
- 素材库逐项加入/替换照片、贴纸和城市印章；照片必需、每类最多一个，装饰可移除。从卡片返回素材库时保留已有组合。
- 实现真实卡片渲染并得到可预览、可交付给 PCD-002 保存/分享的图片资产；渲染成功只在文件/图像实际可读时成立。照片、信息、贴纸、城市印章和固定寄语共同构成可追踪渲染输入版本，避免状态只记 boolean。正式输出规格沿用决定，不杜撰像素尺寸。
- 处理加载/渲染进行中、资源读取/生成失败与重复点击；旧输入的异步结果不能变成新卡片生成结果。无效路由/缺元数据按 Q-015/Q-003 决定；不扩展文字编辑、自由排版或历史作品库。

## 历史实现与暂停状态（后续由恢复开发记录取代）

- `app/postcard/index.tsx` 已能根据 `photoId` 从 store 照片目录解析非 mock 图片 URI，也会根据已知 `decoration` ID 在当前卡片预览中显示对应资源；现有页面回归覆盖这两条输入路径。
- 当前“生成明信片”处理器只将 `generated` 设为 `true`，没有渲染器、文件 URI 或独立可读结果。不得将该状态当作 PCD-001-A03 通过。
- 已检查当前依赖：`jimp-compact` 可用，但其复用的日记长图渲染器画的是结构文字骨架，不能生成当前明信片的原始卡片布局和中文寄语；`react-native-view-shot`、`react-native-svg`、`sharp`、`canvas`、`@napi-rs/canvas` 与 `expo-image-manipulator` 均不可解析。
- 生成当前原生卡片的真实 PNG 需要加入/采用经过批准的原生视图捕获能力；还需让现有生成动作等到资产可读后才显示成功，并在失败时提供反馈。该时序/失败反馈属于冻结的正式交互边界，本轮未改。
- 恢复该分支需用户授权：允许增加原生捕获依赖，并仅调整现有生成动作的完成时机与失败收口（不新增入口、不改布局/视觉）；或提供已批准且无需改变现有反馈的渲染器方案。在授权/方案到位前，CASE-PCD-001-003/004/005 停止并跳过。
- 2026-10-15 用户明确要求先跳过该渲染分支；当前维持暂停，不引入依赖、不改生成按钮时序或失败反馈，也不将未运行的真实图片验收计为通过。

## 2026-10-28 连续随机位置

- 印章位置以 `v2:x:y:rotation` 传递归一化坐标与 -18 至 18 度角度；按原生照片布局宽度换算，为旋转边缘预留 10dp，不改变照片 280dp 高度、卡片尺寸和固定页脚。右侧与地点标记重叠的横向范围映射至下方可用高度，不把随机结果钳到同一条线；旧 `0` 至 `3` 路由位置仍兼容。
- 更换照片或印章、取消后重选印章、目录回传不同印章重新随机；换贴纸、同一照片点击、切步骤、同组合目录回传及预览/保存/分享不重新随机。
- 实际照片宽度与位置进入捕获输入版本，照片未布局时不导出含印章的卡片；宽度变化不重挂载已加载图片，捕获期间宽度变化则丢弃旧结果。
- 定向测试与剩余设备验证见 DEV-88；实际设备目视、原生目录回传与 PNG 独立打开未执行，不将替身导出当作真实文件验收。
