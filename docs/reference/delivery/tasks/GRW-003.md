## 任务内容

- 新日记成功保存后只为该篇日记异步生成一条当前锚点；后续编辑只刷新该篇新版本，不批量重跑其它日记。总结整篇有效 text/quote 段落，持久保存所有来源 block ID；无有效正文时跳过。
- 聊天来源按设备当地日期保存；新一天首次完成 Provider 聊天后，总结未处理的完整对话，多日积压合并一条，不处理功能启用前旧 turn；无新聊天不触发。
- 复用服务端现有 PET_CHAT 模型配置，但采用独立摘要提示词；日记和聊天摘要均为最多 60 字的中文一句话，四主题择最接近者。
- 日记和聊天两种来源进入统一 feed。萌宠入口默认全部按日期排序，成长树继续按主题过滤；卡片跳回来源日记或聊天消息。服务端分页、计数及纠正列表叠加不能由客户端自报来源决定。
- 用户纠正最多 240 字，只覆盖锚点展示；不修改原文、不进入聊天上下文、不转给日记新版本。锚点/纠正同设备隔离并随来源记录存续。
- 失败/旧版回调必须可区分；模型每批总尝试三次、3 秒间隔，耗尽后存后台终态，不回退 mock、不提供人工重试入口。读页面不得展示无来源或失效来源。
- 真实集成区分真实 Provider、隔离 MySQL、设备页面和 mock 证据；不逐字断言摘要、不用固定锚点数替代相关性验证。
