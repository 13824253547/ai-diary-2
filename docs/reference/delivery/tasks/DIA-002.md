## 任务内容

- 编辑会话读取仓库快照并创建隔离草稿；标题/正文/引用修改更新指定块及派生摘要，不直接写已保存对象。
- 用 CRE-005 的真实 AI 服务边界替换 rewriteDraftBlock 固定文案；请求携带选中块、角色及必要照片上下文，作用域限制在目标正文/引用块。
- 重写绑定 draftId、blockId、内容版本与请求 ID；失败保留原文，取消/过期回调不能覆盖新输入。候选采用方式及用户输入冲突由 Q-002/Q-008 确认。
- 保存和放弃统一调用 DIA-005；输入长度按 Q-003，入口由 NAV-001 衔接。

## 当前实现进展

- `app/diary/[id]/edit.tsx` 已具备标题编辑、逐块正文/引用编辑、逐块图片引用与“重写本段”入口；编辑仍基于 `draftId` 工作副本，不会直接改写已保存日记。
- `src/store/create-app-store.ts` 已补齐 `rewriteDraftBlock(...)` 的真实服务边界接线：当前会通过 `CoreDiaryRepository.rewriteBlock(...)` 把 `draftId / blockId / draftVersion / characterId / blockType / content / scoped photoIds` 发到后端，而不是继续使用前端本地固定文案。
- `src/contracts/core-diary-contract.ts` / `src/repositories/core-diary-repository.ts` / `src/repositories/http-core-diary-repository.ts` 已新增 rewrite 请求与结果契约，前端仓库会校验返回结构，畸形结果会按 `provider_failed` 收口。
- `backend/src/modules/generation/generation.controller.ts` / `backend/src/common/memory-store.service.ts` / `backend/src/common/diary-generation.service.ts` 已新增同步 rewrite 接口：后端会先校验草稿归属、版本与可用照片上下文，再由统一 AI provider 生成目标块的新文本。`deterministic` provider 已改为根据原文、角色和照片事实输出确定性改写结果；`openai-compatible` provider 也会走同一 JSON 契约。
- `src/store/create-app-store.ts` 现已把重写请求绑定到“草稿 + 块 + 当前内容版本 + 请求 ID”，同内容重复点击会复用在途请求；手动编辑、放弃草稿、保存完成或旧请求迟到返回都不会让过期结果覆盖新输入或已保存原件。
- `src/store/__tests__/diary-domain.spec.ts` 已补 `DIA-002` 自身的 A01/A02 专属断言：标题修改仅留在工作草稿内，不会提前改写 `diary-1` 或旁边的 `diary-2`；正文块与引用块也能分别修改，且只会更新目标草稿块，未触碰其他段落和已保存原件。
- `src/store/__tests__/diary-domain.spec.ts` 现已补齐 A05 的专属闭环：同一篇日记第一次编辑后放弃会恢复到原始快照且列表数量不变；第二次重新编辑后提交保存，会沿用原 `diary-1` 更新标题和正文，不会新增列表项或串到别的作品。
- `app/diary/[id]/edit.tsx` 已补 A04 页面反馈：当当前草稿没有正文/引用块时，“重写本段”会禁用并展示“当前没有可重写的文字段落”；当先前选中的块已失效时，按钮同样会禁用，并展示“当前选中的段落已失效，请重新点选需要重写的文字。”，不会偷偷改写别的段落。
- `src/store/__tests__/diary-domain.spec.ts` 已补充 rewrite 作用域、失败保留原文、重复触发去重、手动新输入防旧结果覆盖等证据；`backend/src/common/diary-generation.service.spec.ts`、`src/contracts/__tests__/core-diary-contract.spec.ts` 与 `src/repositories/__tests__/http-core-diary-repository.spec.ts` 也已补 rewrite 契约与仓库边界验证。
- `src/store/__tests__/diary-domain.spec.ts` 本轮又补了 A06 的故障矩阵：当 rewrite 返回 `timeout` 或仓库因畸形 payload 收口为 `provider_failed` 时，目标段落会继续保留原文，`issueLog` 会分别记录超时文案与契约错误，不会偷偷写入半成品文本；`backend/src/common/diary-generation.service.spec.ts` 也已补 `openai-compatible` rewrite 请求的超时分类，确认 `AbortError` 会落成可重试 `timeout`。
- `app/__tests__/edit-screen.spec.tsx` 已补无可重写目标的页面级证据：日记不存在时会直接落到空态；没有正文/引用块时会显示禁用态与无目标提示；选中的块失效后也会显示无效目标提示，且不会把“重写本段”误作用到其他段落。
- `app/diary/[id]/edit.tsx` / `app/__tests__/edit-screen.spec.tsx` 本轮又补了 A06 的页面级失败反馈：当段落重写因超时、provider 失败或畸形结果失败时，编辑页现在会把内部错误日志映射成精确的中文提示“重写超时，请稍后重试。”、“重写失败，请稍后重试。”与“重写结果异常，请稍后重试。”，不再只把故障留在 `issueLog` 里。

## 任务验收

- **T-DIA-002-A01：**映射 **DIA-002-AC01**。标题修改只改变草稿；提交前已保存版本保持原值。
- **T-DIA-002-A02：**映射 **DIA-002-AC02**。编辑正文/引用只改变目标块，其他块不被直接改写。
- **T-DIA-002-A03：**映射 **DIA-002-AC03**。选中正文/引用重写后得到可继续编辑的替换文本，其他块保持不变。
- **T-DIA-002-A04：**映射 **DIA-002-AC04**。无可重写块或目标不存在不产生变更并呈现相应无效/空态。
- **T-DIA-002-A05：**映射 **DIA-002-AC05**。编辑保存/放弃结果遵循 DIA-005；质量按 Q-002，不验收固定示例正文。
- **T-DIA-002-A06：**【工程新增】重写失败/取消保留原文，旧版本结果不覆盖新输入，重复触发按请求契约去重。

当前已形成真实代码与自动化证据的是 A01、A02、A03、A04、A05、A06；剩余未完成部分主要受 Q-002 / Q-003 / Q-008 约束，集中在真实重写质量、文本边界和候选覆盖策略，不再是页面级失败反馈缺口。

## 必要待定规则

Q-002 阻塞重写质量、时效及重试；Q-003 阻塞文字边界；Q-008 阻塞重生成覆盖；Q-001/Q-009 分别阻塞留存/入口。 详见[问题清单](../../business-spec/open-questions.md)。
