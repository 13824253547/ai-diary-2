## 任务内容

- 把当前 hasPhotoPermission 布尔值和直接 grantPhotoPermission 改为系统权限适配器；业务授权说明先于系统请求和照片读取。
- 权限请求绑定 draftId，允许结果沿用有效草稿；拒绝/关闭清理未保存新建草稿。对撤回、请求失败、重复点击和晚到回调执行契约中的状态校验。
- 读取范围、有限访问和从设置恢复依据 Q-018；默认隐私属于草稿初始化规则，不能随授权改变。

## 任务验收

- **T-CRE-001-A01：**映射 **CRE-001-AC01**。未授权开始创作先见用途说明；未完成授权不能进入选择或读取照片。
- **T-CRE-001-A02：**映射 **CRE-001-AC02**。允许后进入照片选择，草稿 ID、有效照片选择和角色保持不变。
- **T-CRE-001-A03：**映射 **CRE-001-AC03**。暂不允许或关闭不进入选择，未保存新建草稿被放弃；系统拒绝流程按 Q-018 补定。
- **T-CRE-001-A04：**映射 **CRE-001-AC04**。初始化新建草稿为私密；授权不改变公开范围。
- **T-CRE-001-A05：**【工程新增】重复权限回调及关闭后的旧回调不重复导航或复活已放弃草稿；系统拒绝/撤回不伪装成授权成功。

## 必要待定规则

Q-018 阻塞完整/有限/拒绝/撤回流程、读取范围及设置恢复；Q-001 阻塞重启草稿恢复；Q-009 仅影响浏览排版师入口衔接。 详见[问题清单](../../business-spec/open-questions.md)。

## 执行记录

- 已把原本的 `hasPhotoPermission + grantPhotoPermission` 本地布尔流改成真实权限适配器：
  - `src/services/photo-permission.ts`
  - `src/store/create-app-store.ts`
  - `app/permission/photos.tsx`
  - `app/_layout.tsx`
  - `app.json`
- 当前已落地能力：
  - 应用启动时会通过 `expo-media-library` 同步当前系统相册权限状态，区分 `full / limited / denied / revoked / unknown`，不再只靠内存布尔值判断。
  - 权限说明页只有在用户点击“允许访问相册”后才会触发系统请求；未授权时不会直接把状态写成成功，也不会绕过说明页进入相册。
  - 权限请求已绑定 `draftId`；授权成功后会沿用原草稿进入相册选择，不再补建第二个草稿。
  - 点击“暂不允许”或关闭说明页会放弃未保存的新建草稿；关闭后的迟到授权结果不会重复导航，也不会把已放弃草稿复活。
  - 权限页现已补同步请求锁：同一帧内重复点击“允许访问相册”只会发起一次系统权限请求，不会并发推进第二次授权流程。
  - 草稿默认隐私仍保持 `private`；本轮授权链路不会把草稿公开范围改写成公开态，授权成功后也继续沿用私密初始化值。
- 已补页面级测试：

- 已有验证证据：
