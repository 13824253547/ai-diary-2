## 任务内容

- 将固定初始月份和内存过滤接入已保存仓库查询；月份、日期、搜索词与查询版本统一管理，排序/分页遵循 BAS-001。
- 关闭筛选弹层仅控制显示，保留已选日期；取消日期须用明确操作。搜索范围为标题/摘要/地点，不默认扩展正文全文搜索。
- 统一周条、月历、列表及近期分组的日期归属计算，跨日/月/年按 Q-004；禁止固定年份、天数或 mock 空态回退。
- 处理空数据、失败、取消和请求乱序；新查询结果只接受对应参数版本，保存后各入口读取同一作品。

## 任务验收

- **T-DIA-006-A01：**映射 **DIA-006-AC01**。可选有记录月份或全部回忆，月份来自已保存数据。
- **T-DIA-006-A02：**映射 **DIA-006-AC02**。单日记录选月份后显示该月、选日期后显示该日；关闭弹层保留已选筛选。重新选择月份清除日期筛选；“显示全部”清除月份和日期筛选，结果覆盖全部已保存记录。
- **T-DIA-006-A03：**映射 **DIA-006-AC03**。标题/摘要/地点片段搜索只返回匹配，无匹配显示空态。
- **T-DIA-006-A04：**映射 **DIA-006-AC04**。单日记录日期有可见标记；跨日/月标记与列表口径按 Q-004 补定。
- **T-DIA-006-A05：**映射 **DIA-006-AC05**。点击结果打开对应详情；近期分组是否服从筛选按 Q-004。
- **T-DIA-006-A06：**【工程新增】查询失败与无数据分开，旧请求不能覆盖新条件结果；没有固定示例作品/月份回退。

## DEV-1 实施补充

- 源码审计发现远端回忆 hydration 与页面筛选都只请求 `page=1&pageSize=100`，没有续取后续页；作品超过 100 篇时可静默缺失回忆、月份和搜索结果。
- `src/contracts/core-diary-contract.ts` 定义页容量为 10/20/50/100；`backend/src/modules/memories/memories.controller.ts` 拒绝非法页码和不支持的页容量；`src/repositories/http-core-diary-repository.ts` 新增 `listAllMemories(...)`，校验每页元数据/总数/重复 ID 后顺序聚合完整集合。
- `src/store/create-app-store.ts` 的启动 hydration 与现有回忆筛选接线优先使用全页 repository 能力，缺少该可选方法的既有 adapter 保持原单页兼容；未改变正式页面结构、筛选或反馈行为。
- 新增了 contract/repository/controller 回归代码，但尚未执行 Jest 或 e2e；本轮 typecheck/backend build 仅用于编译确认，不计 CASE 通过。原 Q-004 跨日/月与近期分组规则保持待决。
- DEV-3 日期边界补充：`core-diary-v1` 明确 `month=YYYY-MM`、`day=YYYY-MM-DD` 必须是 Gregorian 有效日期；页面内部点分隔筛选值会先转换成 wire format，前端 query contract/repository 在请求前 fail closed，后端 controller 在读数据前返回 `invalid_input`，避免非法日期伪装成空结果或误拒绝正常筛选。无效日期及 wire-format regression 已写未运行；Q-004 时区、跨日/月归属与近期分组未改变。
