# T-BAS-005 账号认证与匿名身份替换

状态：进行中。复杂度：L。依赖：BAS-001、BAS-003、BAS-004。契约：[账号认证 v1](../contracts/account-auth-v1.md)。

2026-11-19 开发核查：注册、登录、邮箱码、拼图和注销均已有本地接线；修复了会话跨服务地址复用、验证码错误后无法重试、事务失败提前消耗验证码、并发登录及限流首次写入冲突。隔离 MySQL 定向 E2E 已执行；真实 SMTP 注册/注销收件、iPhone 拼图和生产环境尚未验收或部署，见开发台账。

## 范围

- 实现用户名/密码注册、登录、自建拼图验证码和单活跃会话。
- 以服务端账号主体替换客户端设备身份与 `x-device-id`，完成全部业务 API 的账号数据隔离。
- 增加必须登录的启动门禁、“我的”账号入口、登出和永久注销。
- 按用户最新要求保留旧匿名云端及本机数据原状，不读取、不兼容、不迁移或清理；新账号使用独立数据资源。
- 更新隐私披露和交付追踪。生产数据清理与生产部署需独立核对目标，不属于自动化测试。

## 验收条件

- **T-BAS-005-A01 注册与邮箱**：合规用户名/密码和必填唯一邮箱可注册；注册前通过拼图获取邮箱验证码，验证码有效期10分钟、最多校验5次、单次消费；密码仅以 Argon2id 哈希保存。
- **T-BAS-005-A02 登录与会话**：正确凭证和新鲜拼图可登录；失败响应不泄露账号存在性；同账号新登录原子撤销上一 session。
- **T-BAS-005-A03 数据隔离**：业务请求从可信服务端主体获取 `userId`；A 无法读取或修改 B 的任何私密对象；无 `x-device-id` 身份路径。
- **T-BAS-005-A04 启动与登出**：未登录只可访问登录/注册；Keychain 会话恢复成功后加载账号数据；登出撤销当前 session、清 token 和内存状态。
- **T-BAS-005-A05 永久注销**：先验证当前密码并向已验证邮箱发码；注销时再次验证密码和邮箱验证码，经二次确认后撤下公开内容并删除账号及关联数据/文件；失败不报告成功，文件清理失败可重试。
- **T-BAS-005-A06 新旧数据隔离**：新账号不读取或迁移旧匿名数据；部署与应用启动不清理或修改旧数据，新数据库和媒体目录独立。
- **T-BAS-005-A07 移除旧认证**：运行路径不包含 App Attest/安装密钥身份注册、`x-device-id` 或匿名降级；iOS 不再声明 App Attest entitlement。
- **T-BAS-005-A08 隐私披露**：政策和上架材料准确描述用户名、邮箱验证及账号数据关联、无密码找回方式、SMTP邮件投递和注销入口；不虚构备份清除时限。

## 执行边界

- 注册和登录均要求自建服务端拼图挑战，challenge 过期、错用途、错误和重放均拒绝。
- 注册拼图用于发起验证码投递；只有验证邮箱验证码后才能创建账号。邮箱仅用于注册与注销验证，不用于密码重置。
- 密码找回不在范围内；界面必须在注册前说明忘记密码后的后果。
- 注销继续要求当前密码和二次确认，并额外要求发送到账号已验证邮箱的单次验证码。
- 单账号单活跃 session，不实现多设备同时访问。
- 禁止将旧数据迁入账号。生产数据/文件不可逆删除需独立核对实际目标；不得在开发数据库上试跑。
- 测试 E2E 必须通过 `backend/test/e2e-database-safety.ts` 并注入 `E2E_DATABASE_URL`。
- 本任务不改变 CRE-002 的选图规则及其它既有 UI/UX。
