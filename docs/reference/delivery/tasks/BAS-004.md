# T-BAS-004 测试运行环境与回归资产

状态：已完成。A01～A05 均已有当前代码、可执行测试或报告证据；真实 iOS、文件系统及外部服务集成仍由对应业务 CASE 单独验收。关联：[案例生成约定](../execution-context.md)、[原测试证据](../../business-spec/requirement-matrix.md)。

## 任务内容

1. 建立适用于当前 Expo/React Native 版本的领域/组件、服务/存储集成和 iOS 用户流程测试运行方式，记录本地执行命令。
2. 复用现有 15 个领域场景，逐步解除对 mock 全局集合的依赖；给测试注入可控存储、服务、时钟和 ID，隔离每例状态。
3. 按同名案例生成测试代码，保留 CASE/任务验收关联；真实相册、AI、文件和第三方渠道放入独立集成执行入口。
4. 为异步等待、错误注入、重启加载、图片/PDF检查和人工视觉结果提供证据；以“状态达到条件”等待，不用固定 sleep 作为成功依据。
5. 输出逐例执行报告并对失败返回失败结果；缺少设备/服务时记录阻塞，不当作通过。任务报告中保留未自动化案例。

- **T-BAS-004-A01**：在清晰的安装前置下，可用记录的命令运行类型检查、领域/组件及集成测试；失败命令返回非零。（新增实施验收）
- **T-BAS-004-A02**：现有 15 个场景保留覆盖或有逐项迁移说明；测试重复执行和改变顺序不会因共享状态互相影响。（E01～15；新增实施验收）
- **T-BAS-004-A03**：可注入超时、重复/乱序回调、写失败和权限变化；用例断言可观察业务结果，而非仅断言调用实现函数。（新增实施验收）
- **T-BAS-004-A04**：真实与替身执行报告标明环境、CASE、结果和证据；待决策/阻塞/人工项可见，不以 skip 数量隐去。（新增实施验收）
- **T-BAS-004-A05**：一个经刻意引入的业务错误能使对应测试失败；修复后同一测试通过。（新增实施验收）
