# AI 质量评测基线 v1

版本：`ai-quality-evaluation-v1`

适用范围：第一阶段已进入真实业务链路、但 `Q-002` 仍未最终关闭的 AI 能力。当前先覆盖 `CRE-005` 日记生成；`DIA-002`、`MAT-005`、`PET-001`、`GRW-006` 后续沿用同一结构。

## 目的

- 让 `CASE-BAS-001-004` 和 `CASE-CRE-005-010` 在真实供应商接入前就具备可执行的评测底座。
- 自动校验结构、照片归属、人物引用和任务输出完整性。
- 为人工评测提供固定样本、统一维度和留档格式。
- 明确这是一阶段工程基线，不替代 `Q-002` 的正式产品阈值。

## 当前结论

- 自动校验必须全部通过，否则不能把结果判为“可编辑成功”。
- 人工评测暂不设产品级硬阈值，只记录统一维度；若某维度连续出现 `0`，说明 provider 还不适合进入真实联调。
- 不允许用固定 mock 正文逐字断言质量，也不允许拿生成耗时秒数冒充质量结论。

## 自动校验项

`CRE-005` 当前自动校验这些硬约束：

- 标题非空
- 摘要非空
- 地点与日期存在
- `coverPhotoId` 来自输入照片集合
- `posterPhotoIds` 全部来自输入照片集合，且最多两张
- 正文块数严格等于输入照片数；按输入顺序每块只引用一张对应照片
- 不产生独立 `quote` 块；引用式句子可写在对应正文块中
- 所有图片引用都来自输入照片集合
- 需要图片块的夹具必须产出至少一个图片块
- 人物候选的 `photoIds` 与 `avatarPhotoId` 都必须来自输入集合

这些校验由以下代码执行：

- `backend/src/common/diary-generation-evaluation.ts`
- `backend/src/common/diary-generation-evaluation.spec.ts`

## 人工评测维度

人工评测统一使用 5 个维度，暂按 `2 / 1 / 0` 记录：

| 维度 | 说明 |
| --- | --- |
| 照片贴合度 | 标题、摘要和整篇内容是否明显来自输入照片，而不是泛化空话 |
| 单图事实贴合度 | 第 i 个正文块是否准确描述第 i 张照片可见的内容，没有串图或添加画面无法证明的事实 |
| 跨段连贯性 | 所有段落是否形成同一趟旅程的起承转合，前后自然衔接，没有重复或自相矛盾 |
| 排版师文风区分度 | 不同 `characterId` 是否带来可感知语气差异，同时保持自然中文表达 |
| 可编辑性 | 结果是否适合进入编辑页继续修改，而不是一次性长文堆叠 |

评分说明：

- `2 = 满足当前工程基线`
- `1 = 可用但明显需要人工润色`
- `0 = 明显不合格，暂不建议作为真实 provider 输出`

这里的 `2 / 1 / 0` 只用于当前仓库执行记录，不等同于最终产品通过阈值。

### 排版师文风对照方法

- 使用同一组获授权的受控测试照片，保持照片顺序、模型、生成参数和事实输入一致，分别以 tsuki、路易、拉尔夫生成；至少包含有人物和纯风景两类样本。不同题材的三份输出不能直接比较风格。
- 隐去角色标签，由人工对照标题、摘要及正文评价：tsuki 的局部细节与轻快长短句、路易的风景与舒展来信口吻、拉尔夫的少量细节与简洁停顿，是否能在不依赖固定开头和角色名称的情况下辨认；同时记录照片事实错误、虚构同行者和套话。
- 风格差异不得以牺牲照片归属、真实信息、自然中文和可编辑性换取；结构单测和确定性夹具只能证明提示词存在及契约稳定，不能证明真实模型输出可辨认。此对照需取得真实 Provider 调用授权后执行，并沿用 Q-002 的待定质量阈值。

## 执行方式

运行下面命令会使用 `deterministic` 结构夹具对固定样本生成报告，不调用真实 provider：

```bash
npm --prefix backend run eval:diary-generation
```

日记实际运行链路的 provider 解析顺序为：

- `DIARY_GENERATION_PROVIDER` 显式设置优先
- 未设置且 `PET_CHAT_PROVIDER=ark-openai-compatible` 凭据完整时，复用其 Ark endpoint、model 和服务端 API key
- 否则沿用 `AI_PROVIDER`；生产环境没有真实 provider 时 fail closed

本 fixture runner 会将 provider 临时固定为 `deterministic`；若设置非 `deterministic` 的 `DIARY_GENERATION_EVAL_PROVIDER`，runner 会在发起请求前 fail closed。固定夹具只有照片 ID、没有图像文件，因此不具备真实图像理解或文风评测资格。真实质量评测必须另备受控测试图片并获得真实 provider 调用授权；不得读取或上传个人相册作为自动评测素材。

输出文件：

- `docs/reference/delivery/reports/cre-005-quality-baseline.md`
- `docs/reference/delivery/reports/cre-005-quality-baseline.json`

## 与 Q-002 的边界

当前仍未确认：

- 正式产品级质量阈值
- 超时秒数与取消策略
- 自动重试次数与覆盖策略
- 费用、次数和 provider 选择

因此本基线只负责：

- 让结构校验可运行
- 让固定样本可复现
- 让人工评测维度有统一模板

它不会宣称 `Q-002` 已关闭，也不会把当前确定性 provider 的输出当作真实 AI 质量通过。
