# 账号认证契约 v1

状态：开发中。邮箱验证增量按 2026-11-10 用户确认建立；尚未表示任何 CASE 已通过。

## 身份与账号

- 账号使用用户名、密码和必填且唯一的已验证邮箱，不收集手机号，不提供密码找回或客服重置。邮箱仅用于注册验证与永久注销验证。
- 用户名为 4–32 位 ASCII 字母、数字或下划线；比较前统一转小写，数据库唯一约束也使用规范化值。
- 邮箱去除首尾空格并转小写后存储；每个邮箱仅绑定一个账号。服务端不向客户端返回邮箱验证码。
- 密码长度为 8–128 个字符；服务端以 Argon2id 随机盐哈希保存，不存明文。
- 账号是业务数据的唯一所有者。业务 ID 从服务端认证主体获取，客户端不能提交或替换所有者 ID。
- App Attest、安装级 Ed25519 密钥、硬件/设备指纹及 `x-device-id` 不参与账号身份或业务授权。

## 拼图挑战

- 注册、登录均须先完成自建拼图挑战。
- 服务端生成并保存带用途绑定的短时一次性 challenge；客户端只能提交拖动位置，不能提交“已通过”标志。
- challenge 成功、失败、过期或重复使用均进入终态；不得重放。挑战失败后重新获取新的挑战。
- 对挑战生成/校验、用户名摘要、来源 IP、登录失败进行限流。IP 仅作短期防滥用，不作用户身份。
- 登录失败采用不泄露账号是否存在的统一响应。

## 邮箱验证

- 注册先完成用途为 `register` 的拼图，再向用户邮箱发送 6 位验证码；完成验证码后才能创建账号和签发会话。
- 邮箱验证码 10 分钟有效、最多校验 5 次、成功后原子消费且只能使用一次；重发会使之前的验证码失效。
- 按来源 IP、邮箱地址和操作用途限流；验证码只以使用 `ACCOUNT_AUTH_JWT_SECRET` 生成的 HMAC 摘要保存，不写入日志或响应。
- 企业邮箱 SMTP 由服务端发送；SMTP 用户、密码及发件地址只配置在后端环境变量中，不进入客户端包。
- 注销验证码发往账号已验证邮箱。发码请求先验证当前密码；最终注销仍需再次提交当前密码、验证码并经过页面二次确认。
- 邮箱验证不提供密码找回功能。忘记密码后仍无法自行恢复账号。

## API 约定

- `POST /api/auth/captcha`：请求注册或登录用途的拼图，响应 challenge ID、背景图和拼图块图像、有效期及必要的渲染尺寸。
- `POST /api/auth/register/email-code`：提交 email 和注册拼图位置；服务端消费拼图并发送邮箱验证码，返回不含验证码的 challenge ID 与有效期。
- `POST /api/auth/register`：提交 username、email、password、邮箱验证码 challenge ID 和验证码；验证码原子消费后创建唯一邮箱账号与唯一活跃会话。
- `POST /api/auth/login`：提交 username、password、challenge ID 和归一化拖动位置；校验成功后撤销账号原会话并创建新会话。
- `GET /api/auth/me`：返回当前账号最小资料。
- `POST /api/auth/logout`：撤销当前 session，重复调用幂等。
- `POST /api/auth/account/deletion-code`：要求当前有效 session 和当前密码，向账号已验证邮箱发送注销验证码。
- `DELETE /api/auth/account`：要求当前有效 session、再次提交密码、邮箱验证码并确认注销；撤下公开内容并删除账号数据及文件。失败不得报告注销成功。
- 业务请求仅使用 `Authorization: Bearer <token>`。服务端从已验证 token 的 `userId` 与 `sessionId` 建立可信请求主体。

## 会话与安全

- 每个账号最多一个有效 session。注册或登录必须原子撤销旧 session 并签发新的服务端 token。
- token 包含 `sub=userId` 和 `sid=sessionId`，签名、到期时间和数据库 session 状态均须通过校验。
- 凭证存放于 iOS Keychain，不写入 AsyncStorage、草稿快照、日志或 URL。
- 邮箱验证码用于确认邮箱控制权及注销意图，不作为密码找回或单独登录凭证。
- 登出撤销当前 session 并清理本机 token 与账号态；账号注销撤销 session 并清除账号数据。
- 无效/过期/已撤销 token 返回统一的认证失败；客户端不得降级为匿名设备身份或读取另一个账号的本地缓存。

## 数据与历史账号

- 所有业务数据按账号 ID 隔离；禁止客户端指定 owner。
- 本契约切换不认领、不合并旧匿名身份。切换操作会删除旧身份云端业务数据、公开内容和媒体资产，并清除本机旧匿名应用私有草稿/缓存；系统相册原图不删除。
- 自动化清理只允许指向显式隔离的 `E2E_DATABASE_URL`。生产清理必须单独核对数据库和媒体目录目标，不能由常规启动或测试流程触发。
- 第三方服务日志及备份只按已核实的供应商策略处理，不承诺超出系统控制范围的即时物理清除。
