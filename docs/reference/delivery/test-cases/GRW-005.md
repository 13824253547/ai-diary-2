# GRW-005 自动成长与花朵测试案例

**关联任务：** [T-GRW-005](../tasks/GRW-005.md)。**状态：部分执行（DEV-64 客户端自动化及隔离 MySQL 子集已执行；真实模型质量/用户设备来源验收待补）。** 遵循[共同约定](../execution-context.md)。成长数值必须来自设备隔离读模型，不从 mock 初始两朵推断。

## 可执行设计

### CASE-GRW-005-001 真实主题、进度与加载态

**覆盖：** T-GRW-005-A01。**层级：** 组件 / 契约。
**前置数据：** 一组真实成长读模型含主题、里程碑状态和当前进度，另有空 / 未加载夹具。
**操作：** 延迟读取结果后打开花朵页，依次返回有数据与空状态。
**明确预期：** 有数据时三花状态、模型短说明及里程碑等于服务端读模型；首次旅行来源可追溯。加载、无日记、服务失败不伪装为固定 2/3 或固定里程碑进度。

### CASE-GRW-005-002 未解锁拦截

**覆盖：** T-GRW-005-A02、T-GRW-005-A04。**层级：** 端到端 / 权限集成。
**前置数据：** 设备服务端仅有 0～2 类真实 GrowthFlower 授予。
**操作：** 点击报告入口，随后直接请求报告 API 或直达 `/profile/report`。
**明确预期：** 花朵按服务端状态显示锁定；入口说明集齐三类才解锁；API 返回 `not_unlocked` 且不生成、不返回报告正文。客户端状态/路由参数不能授权。

### CASE-GRW-005-003 已解锁访问一致

**覆盖：** T-GRW-005-A03、T-GRW-005-A04。**层级：** 真实读取集成 / 端到端。
**前置数据：** 隔离库中当前设备有三类真实来源支持的 GrowthFlower 记录。
**操作：** 从树进入花朵，查看状态并点击报告，再重开两页。
**明确预期：** 成长树和花朵页读取同一服务端状态；三花可读后 report gate 才开放，但解锁本身不代表已有报告成功。

### CASE-GRW-005-004 状态写入失败、重试与身份

**覆盖：** T-GRW-005-A06、T-GRW-005-A04。**层级：** 存储 / 契约集成。
**前置数据：** U1/U2 有不同设备状态；模型 Provider 可失败；一条成长任务处于 pending。
**操作：** 注入 Provider 失败，查看失败状态；显式手动重试；重建 Nest 服务读取 pending/running 任务；切换设备读取成长状态。
**明确预期：** 单次失败不会误授花朵/解锁；不自动重试；显式重试创建新尝试；设备/服务恢复时，pending 或批次间任务可继续，带 in-flight 标记且结果不确定的任务必须转为 `interrupted`，不能自动重发，用户显式重试后才产生新请求；U2 不继承 U1 花朵或权限。迁移、启动恢复 hook 与部分持久行为已在隔离 E2E 验证，真实进程重启仍待补。

## 自动成长验收

### CASE-GRW-005-005 三类花朵识别与真实里程碑

**覆盖：** T-GRW-005-A01/A03/A05。**层级：** 决策已局部确认；Provider/隔离 DB 集成。**决策状态：三花与里程碑口径已确认；执行状态：部分执行。**
**前置数据：** 合成日记涵盖三类花、明确旅行证据、重复来源和无有效正文；另有不同设备及可控记录日期。
**操作：** 初次进入执行一次全量识别；保存/编辑日记触发单篇增量；重放任务；对 30 天连续/断档日期和 100 锚点边界验证。
**明确预期：** 仅支持固定三类；每类至多获授一次，摘要来源必须属于该设备当前请求输入；旅行必须有日记证据。30 天只计算最新连续日期段、断档后从 1 重新计；缺少发布日期用入库时间、均无效则排除；30天/100锚点仅展示，不直接授花。Provider 真实质量仍需单独评测。

### CASE-GRW-005-006 重放、乱序与来源编辑

**覆盖：** T-GRW-005-A05/A06。**层级：** 已决策；持久事件集成 / 故障恢复。**决策状态：已确认；执行状态：部分执行。**
**前置数据：** 同设备同日记 V1/V2、baseline、增量任务、不同设备 flower state。
**操作：** 重放相同任务，先回传 V2 后回传 V1，编辑或删除已获花朵来源，并在 worker 停止后重启。
**明确预期：** 旧版迟到结果不能覆盖新任务；唯一键避免重复授予；花朵一旦获授不撤回；不同设备状态隔离；pending 或批次间任务可恢复，in-flight 结果未知时失败关闭、不自动重复提交。启动恢复 hook 已有隔离 E2E 子集，其余故障恢复场景仍待补。

- 客户端 7 suites / 20 tests 覆盖成长树真实状态、花朵页首次初始化/进度/摘要、报告入口、报告锁定/旧报告保留/手动重试、contract/repository/Store 和逐花视觉状态。

- 当前开发库含 9 篇日记；因打开花朵页会自动对真实历史全文做模型 baseline，未在当前用户设备触发真实页面流程，设备页面 CASE 保持待验。
