## 可执行设计

### CASE-PET-001-001 空白消息拦截

**覆盖：** T-PET-001-A01。**层级：** 单元 / 组件。
**前置数据：** 空会话、可计数的聊天服务替身。
**操作：** 分别输入空字符串、空格、换行加空格，触发发送按钮和提交事件。
**明确预期：** 发送不可用；服务请求为零；用户 / 助手消息数量不变。

### CASE-PET-001-002 有效消息与真实回复

**覆盖：** T-PET-001-A02、T-PET-001-A03。**层级：** 真实集成 / iOS 端到端。
**前置数据：** 隔离用户的空会话，真实聊天服务可访问。
**操作：** 输入带首尾空格的当天经历并发送；验证 `POST /chat/conversations/:id/turns` 和回复保存结果，再等待对应服务回复。
**明确预期：** 服务端保存的用户文字已去首尾空白且内部换行保留；真实 provider 有效响应后只出现一条对应的小橘回复；输入清空；两种角色可辨；视图定位末尾。记录请求与保存结果，不以关键词模板证明真实 AI 成功。开发 mock 子例只能证明来源隔离与持久编排，不能代替本 CASE 的真实 provider 预期。

### CASE-PET-001-003 历史顺序与长会话滚动

**覆盖：** T-PET-001-A03。**层级：** 组件 / 集成。
**前置数据：** 已确认留存契约下保存的多轮会话，消息长度足够超过一屏。
**操作：** 重新打开会话，发送新消息并返回回复。
**明确预期：** 历史角色与顺序等于已保存记录；新用户消息及对应回复各一条追加在对应轮次；最新回复可见，不丢失历史。

### CASE-PET-001-004 键盘提交与取消提交

**覆盖：** T-PET-001-A04、T-PET-001-A01。**层级：** iOS 组件 / 支持的外接键盘端到端。
**前置数据：** Q-003 已确认的键盘环境，输入非空文本。
**操作：** 分别按 Enter 和 Shift+Enter；随后清空文字再按 Enter。
**明确预期：** Enter 产生一次有效提交；Shift+Enter 只增加换行，消息和请求不增加；空输入 Enter 不提交。不支持该事件的设备另按待决策矩阵补例。

### CASE-PET-001-005 网络失败与响应丢失重试

**覆盖：** T-PET-001-A05。**层级：** 契约 / 集成。
**前置数据：** 已确认重试契约；分别注入离线、请求未完成超时、服务完成但响应丢失。
**操作：** 通过 session API 创建 turn，分别记录固定 failure code、重试同 requestId 的下一 attempt，再重放失败/成功响应；另在客户端注入离线、超时及响应丢失。
**明确预期：** 服务端只持久化 `timeout` / `cancelled` / `provider_failed`，不保存异常原文；完成前没有助手消息；失败可恢复；同一 request 不重复用户消息；旧 attempt 被拒绝，当前 attempt 成功后仅保留一条助手消息。页面的可见失败/重试仍需正式入口接线并验证，mock 不替代真实 AI。

### CASE-PET-001-006 重复点击与乱序回调

**覆盖：** T-PET-001-A05、T-PET-001-A02。**层级：** 单元 / 契约。
**前置数据：** 两个可区分请求 R1、R2；服务返回请求标识，允许控制响应次序。
**操作：** 双击同一次发送，随后执行另一轮消息；先返回 R2，再返回 / 重放 R1；随后通过会话 GET 读取历史。
**明确预期：** 同一发送意图仅保存一次；每条回复归属原请求和会话；历史按 turn sequence 返回用户消息及对应回复，不因响应到达先后而串轮；重放不增加助手消息。若服务契约禁止并行，R2 应先排队且不会丢失。

### CASE-PET-001-007 留存与身份隔离

**覆盖：** T-PET-001-A06、T-PET-001-A03。**层级：** 真实存储集成。
**前置数据：** Q-001 的保留期限内，用户 U1、U2 各有不同会话。
**操作：** U1 写入消息后通过设备身份读取会话；切换 U2 查询会话列表与详情并尝试读取/写入 U1 的 conversation ID；延迟交付 U1 的旧请求，再回 U1；使用隔离数据库验证进程重启后的回读。
**明确预期：** 服务只返回当前 device ID 拥有的会话；U2 不能读取或写入 U1 数据；旧 U1 回调不能显示到 U2；U1 重开恢复范围须符合 Q-001。未确认 Q-001、未应用 migration 或未准备隔离数据库时，留存端到端保持未执行。
