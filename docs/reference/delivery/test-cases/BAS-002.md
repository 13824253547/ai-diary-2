# T-BAS-002 测试案例

关联：[任务](../tasks/BAS-002.md)、[环境与夹具](../execution-context.md)。状态：部分执行。

## CASE-BAS-002-001 请求与失败传播

覆盖：T-BAS-002-A01。层级：契约集成。
前置：可控服务返回正常、离线错误及结构错误三种结果。
步骤：分别调用同一服务能力，观察请求与返回状态。
预期：请求字段符合契约；正常结果被接收，两种错误不被当作成功，不产生固定 mock 作品或回复。

## CASE-BAS-002-002 供应商凭据边界

覆盖：T-BAS-002-A02。层级：构建与服务集成。
前置：使用可识别的测试供应商秘密配置后端，生成测试客户端包并发起请求。
步骤：检查客户端源码配置、构建资源、请求/响应及客户端日志中是否含测试秘密。
预期：客户端上述位置均不存在供应商秘密；后端可以凭该秘密完成服务调用。

## CASE-BAS-002-003 数据归属与公开投影

覆盖：T-BAS-002-A03。层级：后端集成。
数据：身份 U1/U2 各有私密日记、草稿、聊天和锚点；U1 有一篇选段匿名作品。
步骤：以 U2 替换各目标 ID 请求 U1 私密对象的读取/修改；通过公开入口读取匿名作品。
预期：越权拒绝且数据不变；公开入口只含允许段落/照片和匿名结果，无完整私密对象。
当前执行：已通过 `backend/test/app.e2e-spec.ts` 验证草稿读取、生成任务读取、日记读取与编辑保存的跨设备越权都会返回 `permission_denied`，且其他设备的私密日记不会进入当前设备的回忆列表；同时 `src/services/device-identity.ts` / `src/store/adapters/backend-core-diary-adapter.ts` / `app/_layout.tsx` 已补前端稳定设备身份持久化与启动预热，`src/repositories/__tests__/http-core-diary-repository.spec.ts` 已验证请求会携带对应 `x-device-id`。公开投影部分仍待 `sharing` 接口按允许投影收口后补测。

## CASE-BAS-002-004 重复、取消与版本冲突

覆盖：T-BAS-002-A04。层级：确定性契约集成。
步骤：同幂等键提交两次；取消请求后送迟到结果；发送旧版本更新。
预期：同键只有契约约定的一次副作用；迟到结果不改当前状态；旧版本不会静默覆盖新版本，冲突可被调用方处理。
当前执行：已通过 `backend/test/app.e2e-spec.ts` 验证同设备重复保存仍只返回首次保存结果、不同设备使用同一幂等键不会串号、生成任务取消后状态保持 `cancelled`，以及旧版本编辑会返回 `version_conflict`；同时 `src/repositories/__tests__/http-core-diary-repository.spec.ts` 已验证应用侧请求会带上异步解析出的设备身份请求头。更细的真实服务超时/迟到响应链路仍待后续 AI 适配器接入后补测。

## CASE-BAS-002-005 替身和真实服务两种执行

覆盖：T-BAS-002-A05。层级：测试环境集成 + 真实服务集成。
步骤：以测试适配运行乱序/失败案例，再以已配置测试服务执行一个真实成功请求，保存报告。
预期：两种适配可以选择，报告标明各自环境与请求证据；缺凭据时真实项报告阻塞，不能沿用替身通过结果。
