## CASE-BAS-002-002 供应商凭据边界

覆盖：T-BAS-002-A02。层级：构建与服务集成。
前置：使用可识别的测试供应商秘密配置后端，生成测试客户端包并发起请求。
步骤：检查客户端源码配置、构建资源、请求/响应及客户端日志中是否含测试秘密。
预期：客户端上述位置均不存在供应商秘密；后端可以凭该秘密完成服务调用。
当前执行：`backend/.env` 不存在，未读取或输出任何真实凭据。以 `AI_PROVIDER_API_KEY=<one-time-canary>` 执行 `npx expo export --platform ios --output-dir /tmp/orange-glow-ai-diary-secret-scan-20261015` 得到 4.4 MB iOS JS bundle；新增 `tools/verify-client-bundle-secrets.js` 对该临时导出扫描 102 个文件，canary 零匹配。`npm run test:client-secret-boundary` 的 3 项单测覆盖嵌套文本/二进制资源匹配、无匹配与参数校验。此证据只证明客户端静态导出未内嵌测试值，不代表真实后端凭据调用、请求/响应与客户端日志边界已验收；未发起 provider 请求，CASE 继续 partial，等待操作方配置真实测试凭据及隔离 provider 环境。

## CASE-BAS-002-003 数据归属与公开投影

覆盖：T-BAS-002-A03。层级：后端集成。
数据：身份 U1/U2 各有私密日记、草稿、聊天和锚点；U1 有一篇选段匿名作品。
步骤：以 U2 替换各目标 ID 请求 U1 私密对象的读取/修改；通过公开入口读取匿名作品；另在历史共享 `device-anonymous` 身份下建立私密草稿，再分别省略和发送空白 `x-device-id` 请求读取。
预期：越权拒绝且数据不变；公开入口只含允许段落/照片和匿名结果，无完整私密对象；缺失或空白设备身份必须返回 `device_identity_required`，不得回退到共享身份并读取其私密数据。
当前执行：已通过 `backend/test/app.e2e-spec.ts` 验证草稿读取、生成任务读取、日记读取与编辑保存的跨设备越权都会返回 `permission_denied`，且其他设备的私密日记不会进入当前设备的回忆列表；sharing 保存入口也拒绝另一设备修改公开范围，且失败后目标范围保持不变。同时 `src/services/device-identity.ts` / `src/store/adapters/backend-core-diary-adapter.ts` / `app/_layout.tsx` 已补前端稳定设备身份持久化与启动预热，`src/repositories/__tests__/http-core-diary-repository.spec.ts` 已验证请求会携带对应 `x-device-id`。后端缺失身份不会回退到共享 `device-anonymous`：有该旧 ID 草稿时，省略请求头的草稿列表和 `/api/identity/me`、以及发送空白请求头的草稿列表，均返回结构化 `device_identity_required`（HTTP 400）；`backend/src/common/device-identity.spec.ts` 也覆盖缺失、空白及有效 ID 规范化。公开投影部分仍待 `sharing` 接口按允许投影收口后补测，因此本 CASE 继续 partial。

## CASE-BAS-002-004 重复、取消与版本冲突

覆盖：T-BAS-002-A04。层级：确定性契约集成。
状态：已执行。
步骤：同幂等键提交两次；取消请求后送迟到结果；发送旧版本更新。
预期：同键只有契约约定的一次副作用；迟到结果不改当前状态；旧版本不会静默覆盖新版本，冲突可被调用方处理。
当前执行：`backend/test/app.e2e-spec.ts` 已在隔离 MySQL e2e 中验证同设备重复保存只返回首次结果、跨设备同键不串号、生成任务取消保持 `cancelled`、来源版本旧值返回 `version_conflict`；旧/迟到生成回包由领域回归验证不覆盖当前轮次。新增 `ApiClient` 传输超时和 `AbortSignal`，`HttpCoreDiaryRepository` 将 timeout/cancelled 映射回契约错误，新增回归覆盖请求超时、主动取消及保存/建单响应不确定时使用原幂等键追认。验证：隔离 backend e2e 39/39、API/repository 三套件 30 项、领域定向 2 项、完整前端 37 suites / 298 项及 typecheck 通过；本 CASE 在当前验收范围内通过，真实 provider 质量/重试次数仍属 Q-002，不由本 CASE 决定。

## CASE-BAS-002-005 替身和真实服务两种执行

覆盖：T-BAS-002-A05。层级：测试环境集成 + 真实服务集成。
步骤：以测试适配运行乱序/失败案例，再以已配置测试服务执行一个真实成功请求，保存报告。
预期：两种适配可以选择，报告标明各自环境与请求证据；缺凭据时真实项报告阻塞，不能沿用替身通过结果。

正文与公开范围补充证据（CASE-BAS-002-003）：保存 API 现要求完整 `contentSnapshot`；后端以 MySQL 验证保存后正文、引用、图片块同时从详情与回忆接口读回。非私密范围的 `publicBlockIds` 只接受快照中的文本/引用 block，未知 ID 与图片 block ID 返回 `invalid_input`；省略 `x-device-id`、发送空白身份头与跨设备改范围仍分别按身份/归属规则拒绝。公开内容读取接口仍未交付，故 A03 保持 partial。
