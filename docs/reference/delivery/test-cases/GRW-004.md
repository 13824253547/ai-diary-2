## 可执行设计

### CASE-GRW-004-001 初值和第一条入口

**覆盖：** T-GRW-004-A01。**层级：** 组件 / 集成。
**前置数据：** 两条可用锚点，首条无纠正，次条保存理解 C2。
**操作：** 打开次条面板再取消；点击底部纠正入口。
**明确预期：** 次条初值为 C2；底部入口目标为首条可用锚点且初值等于其当前理解，不误定位不可用来源。

### CASE-GRW-004-002 空值与有效内容

**覆盖：** T-GRW-004-A02。**层级：** 单元 / 组件。
**前置数据：** 可写锚点，记录写入调用。
**操作：** 分别输入空、纯空白 / 换行和普通非空文字。
**明确预期：** 前两者不可保存且无写入；后者可提交，客户端和服务均拦截空白。

### CASE-GRW-004-003 真实保存与重开

**覆盖：** T-GRW-004-A03、T-GRW-004-A07。**层级：** 真实存储集成 / 端到端。
**前置数据：** 留存契约已批准，可写锚点无纠正。
**操作：** 输入带首尾空格的理解，确认保存后关闭页面并重启，再打开卡片与面板。
**明确预期：** 仅确认成功后关闭 / 标为更新；保存内容已去空白，重开卡片和初值一致，真实仓库可查到纠正，而非内存残留。

### CASE-GRW-004-004 三种取消与原文不变

**覆盖：** T-GRW-004-A04。**层级：** 组件 / 集成。
**前置数据：** 保存理解 C1，源日记版本及正文快照明确。
**操作：** 分别修改后按取消、点遮罩、用系统关闭；另一次正常保存 C2。
**明确预期：** 三次关闭不产生写入，仍是 C1；保存 C2 后仅纠正仓库变更，源日记正文和版本不因纠正而被改写。

### CASE-GRW-004-005 空集合

**覆盖：** T-GRW-004-A05。**层级：** 组件。
**前置数据：** 无可用锚点。
**操作：** 打开集合并检查操作。
**明确预期：** 无底部纠正入口，无幽灵面板或可提交目标。

### CASE-GRW-004-006 写入失败与重复确认

**覆盖：** T-GRW-004-A06、T-GRW-004-A03。**层级：** 契约 / 集成。
**前置数据：** 可写锚点；首次存储失败，另有成功响应丢失夹具。
**操作：** 通过 `PUT /anchors/:anchorId/correction` 提交 `expectedVersion` 与设备作用域 `idempotencyKey`；模拟提交失败，再重试并重放成功请求。
**明确预期：** 失败不标“已更新”且待提交输入可继续；相同请求重试 / 响应重放只形成一次生效纠正，确认后读取值一致。

### CASE-GRW-004-007 并发、旧响应与身份隔离

**覆盖：** T-GRW-004-A06、T-GRW-004-A07。**层级：** 契约 / 权限集成。
**前置数据：** BAS-001 已确认冲突机制；U1 两次纠正版本，U2 无权改 U1 锚点。
**操作：** 控制新旧写入 / 回调次序；切 U2 后送达 U1 回调，再以 U2 直接写入目标 ID；另以过期 `diaryVersion` 和过期 `expectedVersion` 提交。
**明确预期：** 旧版不静默覆盖新值，冲突按契约可见并可恢复；U2 不显示或写入 U1 理解，迟到响应不污染页面。

### CASE-GRW-004-009 设备归属、来源块与版本化 API

**覆盖：** T-GRW-004-A06、T-GRW-004-A07。**层级：** 后端单元 / 隔离数据库集成 / HTTP 契约。
**前置数据：** 隔离数据库中 U1 有带 text/quote block 的日记，并有同设备、同日记版本、状态为 succeeded/provider 的持久锚点；另准备 U2 无权访问的日记、无持久提取记录的 anchor ID、不存在的 block、空白纠正及已提交纠正。
**操作：** 检查 GET 空值与已保存值；分别以缺失身份、U2 身份、不存在 block、旧来源版本、空白文本和正确版本读写；同设备重放同一幂等键，再以该键提交不同正文；先以 command-1 保存 v1，再以 command-2 更新 v2，随后重放 command-1；以相同 `expectedVersion` 并发提交两个不同幂等键；另让日记保存与纠正写入同时竞争来源行锁。
**明确预期：** 所有读写均要求设备身份；越权、错误来源和无效输入不落库；同键同载荷在结果仍为当前版本时只产生一次写入并返回一致结果，同键异载荷拒绝；纠正已被后续命令取代后重放旧键返回 `version_conflict`，不得把新值误报为旧命令成功；并发旧版本得到 `version_conflict`；正确写入返回用户纠正来源及递增版本，原日记正文与版本不变。来源更新先取得锁时，旧版本纠正被拒绝；纠正先取得锁时，更新后该旧版本纠正不能被新版本读取。隔离 migration 未准备前不得连接或改动开发数据库。
