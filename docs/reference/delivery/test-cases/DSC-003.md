**关联任务：** [T-DSC-003](../tasks/DSC-003.md)。**状态：部分执行（TEST-14 后端 MySQL 子集）。** 遵循[共同约定](../execution-context.md)。计数 7 / 3 仅是独立夹具，生产验收读取实际服务数。

## 可执行设计

### CASE-DSC-003-001 点赞成功与取消

**覆盖：** T-DSC-003-A01、T-DSC-003-A02。**层级：** 真实集成 / 端到端。
**前置数据：** 可访问 S1，U1 未点赞；固定隔离夹具初始计数为 7，无其他并发参与者。
**操作：** 点赞等待确认，再取消等待确认。
**明确预期：** 服务中 U1 / S1 点赞关系由无变有再无；计数 7 → 8 → 7，图标和操作语义相同变化；记录真实写入证据。

### CASE-DSC-003-002 列表与详情往返同步

**覆盖：** T-DSC-003-A03。**层级：** 端到端。
**前置数据：** S1 未点赞。
**操作：** 列表点赞成功后打开详情，详情取消成功后返回。
**明确预期：** 两处每次均显示已确认的同一状态和计数；返回列表不需以重启修复旧布尔值。

### CASE-DSC-003-003 幂等与其他故事隔离

**覆盖：** T-DSC-003-A04。**层级：** 契约 / 集成。
**前置数据：** S1 / S2 均未点赞；允许重放同一请求标识。
**操作：** 双击 S1 的一次目标点赞，重放成功响应，再反复点赞 / 取消。
**明确预期：** 每次确认的 U1 / S1 关系最多一条；重放不增加计数，S2 关系与计数始终不变。

### CASE-DSC-003-004 写入失败与响应丢失

**覆盖：** T-DSC-003-A05、T-DSC-003-A04。**层级：** 契约 / 集成。
**前置数据：** 分别注入服务拒绝、离线、成功写入但响应丢失；另有显式 `likesEnabled=false` 的 published story。
**操作：** 点赞后观察，恢复并用同一业务请求重试 / 查询确认。
**明确预期：** 失败可观察，不长期显示未经确认的成功；恢复后与服务一致，响应丢失重试不形成第二条关系或多加一。禁用点赞的记录返回结构化 `interaction_not_available`，不写互动，并与 malformed `liked` 输入的 `invalid_input` 区分。

### CASE-DSC-003-005 点赞取消乱序确认

**覆盖：** T-DSC-003-A05、T-DSC-003-A04。**层级：** 单元 / 契约。
**前置数据：** BAS-001 确认的串行或目标状态版本机制，两个请求可控制回调顺序。
**操作：** 点赞后立即取消，先确认取消再返回旧点赞响应；或按串行契约等待后取消。
**明确预期：** 最终用户意图和服务确认状态收敛为未点赞；旧确认不重新点亮，计数不负数且无双加。

### CASE-DSC-003-006 留存与身份切换

**覆盖：** T-DSC-003-A05、T-DSC-003-A03。**层级：** 真实存储 / 服务集成。
**前置数据：** 留存契约已确认，U1 点赞 S1，U2 未点赞。
**操作：** 终止 / 重开应用读取 U1，切换 U2，再回 U1。
**明确预期：** U1 在批准范围恢复已确认关系；U2 的按钮为其自身状态，不能继承 U1 的点赞；总计数来自服务且不因切换重复增长。
