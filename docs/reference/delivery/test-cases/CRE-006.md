# CRE-006 人物命名测试案例

关联任务：[T-CRE-006](../tasks/CRE-006.md)

状态：未执行

夹具、替身与真实环境以及执行证据格式统一遵循[共同约定](../execution-context.md)。各案例独立初始化；“待决策”先补明确断言再执行。真实集成必须保留请求/资源/存储证据，替身通过不能替代真实交付。

### CASE-CRE-006-001 人物候选分流

- 覆盖任务验收：**T-CRE-006-A01**
- 层级：确定性/服务替身
- 状态：未执行
- 数据/前置：两个独立生成结果：P1/P2 有两个合法候选；P3/P4 无候选。
- 步骤：完成生成并观察导航。
- 明确预期：前者进入命名且仅展示返回候选；后者直接编辑，不虚构自己或同行者。

### CASE-CRE-006-002 独立改名保留正文

- 覆盖任务验收：**T-CRE-006-A02**、**T-CRE-006-A03**
- 层级：确定性/组件与领域
- 状态：未执行
- 数据/前置：G1 有自己和同行者，原正文含“同行人”；保存前快照。
- 步骤：分别输入“我本人”和“林可”；保存名字进入编辑。
- 明确预期：对应人物分别更新、别名依契约保留；其他人物未变；正文、照片引用逐块等于快照。

### CASE-CRE-006-003 名称正式边界

- 覆盖任务验收：**T-CRE-006-A02**
- 层级：契约/待决策
- 状态：待决策
- 数据/前置：Q-003 确认长度 N 和字符计量后，构造 N/N+1、Emoji、组合字符及空白。
- 步骤：从 UI 和请求层分别提交边界输入。
- 明确预期：按 Q-003 写明接受/拒绝或截断规则后执行；不把原型16字符当最终规则。

### CASE-CRE-006-004 跳过保留候选

- 覆盖任务验收：**T-CRE-006-A04**
- 层级：确定性/组件
- 状态：未执行
- 数据/前置：G1 已有两个识别候选且包含原称呼。
- 步骤：点击跳过，进入编辑，读取人物及正文。
- 明确预期：两个候选及照片关系保留、正文不变；不产生跨日记查询或自动套用其他人物姓名。

### CASE-CRE-006-005 空称呼提交回落

- 覆盖任务验收：**T-CRE-006-A05**
- 层级：确定性/领域集成
- 状态：未执行
- 数据/前置：G1 自己和同行者 name 均为空/空格，生成完成。
- 步骤：保存作品，经存储重新读取人物。
- 明确预期：按现 FSD，自己显示“我”、同行者显示“同行人”；正文不被全局替换；空值边界最终须 Q-003 确认。

### CASE-CRE-006-006 写失败无效人物及重复提交

- 覆盖任务验收：**T-CRE-006-A06**
- 层级：确定性/故障与竞态
- 状态：未执行
- 数据/前置：G1 已输入两个新称呼；存储写失败一次；无效候选 U1。
- 步骤：保存返回失败；尝试 U1 更新；再重试并重复成功回调。
- 明确预期：失败保留输入且不导航成功；U1 不影响有效人物；重试只一版本更新、一次导航。

### CASE-CRE-006-007 真实识别结果与保存

- 覆盖任务验收：**T-CRE-006-A01**、**T-CRE-006-A03**、**T-CRE-006-A06**
- 层级：真实集成/AI 与留存
- 状态：未执行
- 数据/前置：真实输入 P1/P2 的已知人脸区域，实际服务返回候选；留存能力就绪。
- 步骤：完成生成、为实际候选命名并保存；按 BAS-003 恢复后读取。
- 明确预期：候选来自真实结果而非 mock personIds；命名/照片关系保存，原正文保持；记录服务与存储证据。

### CASE-CRE-006-008 长期人物记忆范围

- 覆盖任务验收：**T-CRE-006-A03**、**T-CRE-006-A04**
- 层级：评审/待决策
- 状态：待决策
- 数据/前置：Q-010 确认是否纳入跨日记记忆、纠正和正文同步。
- 步骤：按决策补同人改名/同名不同人/误识别场景。
- 明确预期：未确认时不生成自动复用或自动正文替换测试；关闭 Q-010 后补独立规则与案例。
