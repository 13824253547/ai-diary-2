### CASE-CRE-004-001 三种开放角色目录

- 覆盖任务验收：**T-CRE-004-A01**
- 层级：确定性/组件
- 状态：已执行
- 数据/前置：角色目录替身返回三种开放风格及描述。
- 步骤：打开角色选择并逐项比对目录。
- 明确预期：三项 ID、说明与契约一致；目录外角色无可选入口；不读取 mock 第四项作为开放能力。
- 当前执行：已通过 `app/__tests__/character-screen.spec.tsx` 验证角色页只渲染 `character-blue / character-green / character-brown` 三种开放角色，`亮亮 / 老师傅` 等隐藏角色不会出现在可选列表中；页面渲染使用的 `availableCharacters` 与首页排版师入口共用同一能力白名单。

### CASE-CRE-004-002 选择传入生成上下文

- 覆盖任务验收：**T-CRE-004-A02**
- 层级：确定性/契约集成
- 状态：已执行
- 数据/前置：G1 含 P1/P2/P3；目录角色 R2；生成适配器记录输入。
- 步骤：选 R2；触发下一步生成。
- 明确预期：G1 characterId 为 R2；生成请求对应 G1 且使用 R2 及其版本，没有使用默认 R1。
- 当前执行：已通过 `src/store/__tests__/diary-domain.spec.ts` 验证选择 `character-green` 后，`mutateDraft(...)` 会先把最新角色持续同步到远端草稿，再启动生成请求；生成侧读取到的始终是最新角色，不会回退到默认 `character-blue`。

### CASE-CRE-004-003 浏览后授权保留角色

- 覆盖任务验收：**T-CRE-004-A03**
- 层级：确定性/导航与状态
- 状态：已执行
- 数据/前置：权限未决定；首页浏览选择 R2。
- 步骤：浏览选择 R2，完成授权，选择三张图并经过模板页。
- 明确预期：每个步骤有效 draftId 一致、角色仍为 R2；是否再确认由 Q-009 决策，不据当前回角色页判失败。
- 当前执行：已通过 `src/store/__tests__/diary-domain.spec.ts` 验证浏览模式下选中 `character-green` 后，授权、选图、模板页沿用同一 `draftId`，`selectedCharacterId` 与草稿内 `diary.characterId` 都会保持为同一角色；当前只确认角色不会丢失，页面是否需要重复确认仍留待 Q-009。

### CASE-CRE-004-005 目录失败及重复选择

- 覆盖任务验收：**T-CRE-004-A05**
- 层级：确定性/竞态
- 状态：已执行
- 数据/前置：目录请求首次超时可重试；选择请求延迟；G1。
- 步骤：超时后重试目录；快速点击同一有效角色两次并重复回调。
- 明确预期：加载错误可见、重试恢复；同一 G1 只推进一次，不建立重复草稿或生成轮次。
- 当前执行：已通过 `app/__tests__/character-screen.spec.tsx` 验证角色目录首次失败时会展示“排版师目录暂时不可用”，点击“重新加载”后会恢复三种开放角色列表；同文件也已验证浏览模式快速重复点击同一角色时，只会创建一份草稿并导航一次，不会重复推进。
