# 六、中国大陆信息处理要求

本次参考《个人信息保护法》主要条款：

- 第17条：处理前明确告知处理者与联系方式、目的、方式、种类、保存期限和权利程序。
- 第21条：委托处理需约定目的、期限、种类、措施等，并监督受托方。
- 第23条：向其他个人信息处理者提供信息，依法履行接收方告知和单独同意。
- 第28至31条：敏感信息须有特定目的、充分必要性及严格措施，依法单独同意；不满14周岁信息受专门保护并需监护人同意及专门规则。
- 第38至39条：跨境须按实际适用条件完成机制、接收方告知及单独同意；同意不是其他跨境手续的替代品。
- 第47、50条：落实主动删除和便捷权利渠道，拒绝请求应说明理由。

日记自由输入可能包含敏感信息，不能将全部输入一概认定为敏感，也不能一概认定不敏感。普通人像、用于识别身份的生物信息、照片中拍摄位置、连续行踪等应按真实处理目的和风险区分；不要机械照搬所有照片都是生物识别数据的描述。

最低年龄属于产品和法律决策。本次没有默认改为“仅18岁以上”或新建儿童服务；如开放不满14周岁用户，通用政策一段文字不足以代替专门规则和真实监护人流程。

“为生成游记、重写文字、和小橘聊天及整理回忆，我们需要通过服务器将相关照片、文字和必要参数发送给【实际AI提供方】。小橘聊天还会参考近期日记摘要；保存日记后可能在后台整理文字记忆，个人洞察可能处理全部有效日记正文。请查看各用途和数据范围，再选择是否同意。你可以拒绝或之后撤回；相关AI功能将不可用，与该处理无关的基础功能不受影响。”

需要对生成、聊天及记忆、全库分析和配图的范围提供易理解说明。可按用户实际进入功能分层授权，不必每次重复同一弹窗；但新增用途、实质扩大范围或新增接收方时需重新判断授权。

许可记录应包含政策版本、接收方、用途范围、时间、当前身份及撤回状态。授权不能默认勾选；拒绝和撤回须真实阻止客户端及后台继续发送，包含已排队任务和自动重试。

## 敏感内容提示

“照片和文字可能包含你或他人的健康、证件、位置等敏感信息。请尽量不提交无关敏感内容，确认你有权使用涉及他人的资料。需要处理敏感信息时，我们会说明必要性和影响，并依法取得相应同意。”

这类提示只辅助最少数据原则，不能替代依法需要的单独同意或免除运营责任。

## 身份与全部数据删除

“删除将处理本设备身份下的日记、素材、照片副本、聊天、公开内容、记忆和洞察等关联记录，并撤销相关凭证。完成后可能无法恢复。主业务数据预计在【真实期限】内处理，备份将在【真实周期】内退出；依法必须保留的信息会另行说明。请确认是否发起删除。”

流程必须可从应用内发起，可后端人工处理，但应让用户知道时限并收到结果，不强迫普通用户先电话或邮件联系。删除前不能通过索取访问令牌或私钥进行核验。

# 九、App Store 隐私标签准备

这不是最终已提交答案。应按实际发布版与供应商数据实践填写：

| 数据 | 核对标签方向 | 注意事项 |
|---|---|---|
| 图片与素材 | 用户内容：照片或视频 | 服务器长期保存，不能按仅临时处理一概豁免 |
| 日记、聊天、提示词、纠正 | 用户内容：其他用户内容等适用类别 | 聊天并非所有情况下都等同邮件或短信；按问卷定义核对 |
| 设备用户身份 | 标识符：用户ID；设备ID是否适用另核对 | 与私人内容关联，不能仅因随机生成就选不关联 |
| 城市 | 粗略位置 | 对系统坐标、业务城市、第三方处理分别判断，不能隐去城市传输 |
| 自由输入中的敏感信息 | 敏感信息或健康等实际适用类别 | 根据实际接收、存储与处理，不凭“不是医疗应用”全部排除 |
| 请求、错误与安全记录 | 诊断或其他适用数据 | 查真实生产SDK和日志；开发日志不自动代表正式版上报 |
| 跟踪 | 单独核对是否用于跨公司广告或测量等Apple定义的跟踪 | 第三方AI功能处理不自动等于跟踪；无跟踪也不等于不收集 |

通常用途涉及应用功能，AI个性化等还需逐项对照问卷定义。`PrivacyInfo.xcprivacy`与商店标签、政策是不同交付物；现有收集数组为空不能作为“无收集”的证明。

## 部署对政策和上架的影响

- API不应继续指向`127.0.0.1`；正式构建需使用可被审核设备访问的HTTPS服务，并校验生产App Attest配置。
- 政策与用户支持页应能公开访问，但私人照片、日记接口及文件存储仍需身份鉴权。公开政策不等于公开全部静态文件。
- 云商、数据库、文件仓库、持久卷、备份与CDN的实际地区及处理范围须写实；即使只更换主机而未扩大用途，也应复核接收方与隐私披露。发生实质变化时依法重新告知和取得许可。
- 日志、访问控制、密钥、备份删除、客服响应和第三方AI授权必须从“开发计划”成为真实上线流程。部署不能替代这些义务。
- 不在生产服务器执行构建；本次仅修改本地源码和材料，不连接或修改服务器。

## AI标识的官方依据

本次直接读取[《人工智能生成合成内容标识办法》](https://www.cac.gov.cn/2025-03/14/c_1743654684782215.htm)：

- 第四条：适用场景的文本、图片需可感知的显式标识；下载、复制、导出文件也应包含显式标识。
- 第五条：文件元数据应包含生成属性、提供方名称或代码、内容编号等隐式制作要素。
- 第六条：传播平台还涉及上传文件的隐式标识核验、用户声明与疑似内容识别。
- 第七条：提供AI生成合成服务的应用，上架或上线审核需提供标识材料。
- 第八条：用户服务协议需说明方法、样式和管理要求；隐私政策不是用户服务协议。
- 第十条：不得恶意删除、篡改、伪造或隐藏规定标识。

Apple当前审核指南原文的明确AI条款是5.1.2(i)的第三方数据共享许可；未从本次查阅原文确认“所有AI内容必须统一水印”的独立Apple条款。应在审核备注主动说明实际AI能力与标识，而不是把中国大陆规定误称为Apple统一规则。

## 当前实现范围与未验收边界

日记共享`DiaryPaper`、编辑页、分享海报以及日记PDF增加文字提示；当前开放的日记创作模板均经过AI生成，用户编辑不自动移除来源提示。未来若增加纯人工创作或外部导入，应新增可靠的文字来源字段，不可继续无条件标记。

图片根据系统已有`source=generated`、provider来源及服务端`generationRequestId`等记录识别，不做画面AI鉴伪。普通上传照片不按名称或风格猜测来源。新生成素材在入库前加入可见水印和XMP；仍保留在素材库中的历史生成图通过鉴权内容读取时补标，原历史文件不进行批量覆写。新文件复制为日记照片副本后保留文件标识，读取现存素材副本清单时补充生成来源，避免前端恢复时丢失可用的来源记录。

明信片预览、保存与系统分享使用同一包含小标识的截图区域；AI卡片导出PNG增加AIGC元数据，日记PDF增加来源提示和XMP。服务端`sharp`依赖只进入后端，不增加移动端原生依赖。标识使用应用代码及内容编号，不写入身份凭证、提示词或用户资料。

**本次不是全量标识合规验收。** GB 45438-2025完整字段、样式、接收平台互操作仍须专项核验；普通外部上传的AIGC元数据检验、外部用户声明、所有AI聊天/锚点/报告的标识、以及此前已导出的旧文件，未被本次三类入口修改全部覆盖。既有历史日记照片若原素材已删除且文件未带可恢复来源，不能仅凭照片外观倒推生成身份。

已导出文件和第三方副本不能远程补标。可见标识不是安全签名，不应宣称能够证明内容真实性、实名身份或经过人工审核。完整用户服务协议及标识使用约定仍需发行方确认。
