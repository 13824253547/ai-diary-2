# 待确认规则与原型差异

这些事项决定后续正式规格和测试预期。它们不是已确认的功能扩展，也不自动成为当前迭代的开发任务。先由业务确认答案，再更新对应模块和需求追踪矩阵。

“规则未定义”表示目前缺少产品决策；“原型差异”表示已有行为或文案不一致，可定位验证。初稿保留这一区别，避免把缺口生成成错误的测试预期。

## 问题关闭方式

每条问题记录决定、适用版本、确认人/日期和影响需求 ID。决定后更新模块与通用规则；在追踪矩阵补充或调整验收和用例。尚未关闭的问题保持“待确认”，不自动产生确定的异常提示文案、时长、费用、算法或恢复策略。
