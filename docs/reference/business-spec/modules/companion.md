# AI 陪伴

版本：FSD v0.1 · 原型能力基线初稿。范围：萌宠页的小橘聊天、陪伴记忆概览和锚点入口。

本文将原型表达的能力视为产品业务能力，描述用户可感知的输入、流程与结果。【交互已表达】表示可以在原型中完成操作；【展示已表达】表示已有展示意图；【预告未开放】表示入口或文案表达了未来能力。示例内容和固定计数不作为正式业务规则；待确认问题不自动转为验收预期。

## 用户路径

底部导航「萌宠」 → 查看小橘与记忆概览 → 输入并发送消息 → 阅读回复。用户也可以从「记忆锚点」进入成长记忆，阅读原日记并纠正小橘的理解。

## 功能规格

### PET-001 小橘聊天

**证据状态：**【交互已表达】输入、发送、消息展示与自动滚动；【展示已表达】小橘作为持续陪伴者的形象与欢迎语。

**业务目标：**让用户通过对话表达当天的经历和情绪，并收到小橘的陪伴回复。

**前置与流程结果：**

1. 用户进入萌宠页，看到已有会话消息和输入区。
2. 用户输入文字，通过发送按钮或键盘发送动作提交。
3. 会话追加用户消息和小橘回复；输入框清空，列表滚动到最新消息。

**明确规则与异常：**

- 输入仅含空白时，发送按钮禁用，提交不新增消息。
- 消息提交前去除首尾空白；用户消息和小橘消息在会话中按先后顺序展示，并以不同头像和气泡区分。
- 页面重开时按当前设备恢复最近一条已保存会话；从锚点带会话标识进入时优先恢复指定会话。历史读取失败时不按空会话发送新消息，可在原输入区重试；未持久化到服务端的消息不保证重启后恢复。保留期限、删除/清理与跨设备同步仍由 Q-001 确认。
- 原型输入框上限为 500 字符，最终字符计量和限制由 Q-003 确认。
- 输入区表达 Enter 发送、Shift+Enter 换行的键盘行为；不同设备键盘的验收范围由 Q-003 确认。
- 当前回复内容表达情绪安慰、旅行回忆、积极回应及继续倾听四类陪伴意图。关键词分支是演示实现证据，不作为正式 AI 判断算法。
- 小橘应优先回应用户最近一句的真实意图：用户问小橘时先回答，分享情绪时给予有内容的陪伴，而非复述后连续追问；用户没有明确经历时不得替其编造理由或好事。自然收尾不强制每轮反问，必要澄清最多一个问题；小橘自身回应不编造现实生活经历。该对话质量目标尚需用真实模型多轮样本验收。
- 用户已确认小橘聊天只服务于日常经历、情绪陪伴、旅行回忆与日记表达；代码/脚本、小说/故事、广告营销/商业代写等非陪伴生成请求应被拦截并以中文说明范围。
- 明确的自伤/暴力/武器/诈骗/恶意软件/隐私窃取操作请求及提示词覆盖请求应在服务端拦截；用户表达危机感受本身仍属于陪伴输入，应转为安全关怀而非一概拒绝。
- 同一 `x-device-id` 同时只允许一个不同的聊天生成任务；发送中禁用继续发送和重试，服务端并发请求返回 `chat_busy`，相同请求的幂等重连除外。
- 当前拦截由固定规则、提示词和明显输出特征校验组成，不等同于完整语义审核或账号鉴权；规则未命中时仍存在模型误答风险。
- AI 质量评测、超时/取消/重试及危机支持细节仍待 Q-002 确认；以上聊天业务范围和明显风险内容拦截为用户局部确认规则。

**验收条件：**

- **PET-001-AC01：**输入空字符串或仅含空白的字符串时，发送按钮不可提交，会话数量不变。
- **PET-001-AC02：**发送含非空内容的文字后，会话显示去除首尾空白的用户消息，并显示一条小橘回复，输入框清空。
- **PET-001-AC03：**用户消息和小橘回复具有可辨识的角色展示；新增消息后列表定位到会话末尾。
- **PET-001-AC04：**在支持相应键盘事件的原型运行环境中，Enter 提交消息，Shift+Enter 添加换行且不提交。
- **PET-001-AC05：**超出陪伴范围或命中明确危险操作规则的输入，在服务端持久化与模型调用前拒绝；客户端显示固定中文范围说明，拒绝内容不提供重试入口。危机感受表达仍进入支持性陪伴流程。
- **PET-001-AC06：**同一设备身份存在活动生成任务时，不允许再创建或重试另一聊天任务；界面阻止发送，服务端拒绝并发 turn。相同 request 的幂等重放仍指向同一任务。

**源码证据：**[萌宠页](../../../../app/(tabs)/pet.tsx#L16)；[输入与发送](../../../../app/(tabs)/pet.tsx#L40)；[消息处理](../../../../src/store/use-app-store.ts#L194)；[会话消息类型](../../../../src/types/diary.ts#L41)。

**待确认问题：**Q-001 会话的保留期限、删除/清理与跨设备范围（同设备最近会话重启恢复已局部确认）；Q-002 AI 的上下文来源、回复质量、时效、等待 / 失败 / 重试及安全回应；Q-003 输入长度、字符计量、多行输入和平台键盘边界。

### PET-002 陪伴记忆概览与锚点入口

**证据状态：**【交互已表达】打开记忆锚点；【展示已表达】小橘形象、名称、已记录日记数量及记忆锚点数量。

**业务目标：**使用户了解小橘陪伴积累的内容，并能够查看小橘记住的具体回忆。

**前置与流程结果：**

1. 用户进入萌宠页，看到「小橘记住了你的」概览。
2. 用户点击「记忆锚点」，进入锚点阅读页。
3. 后续阅读与纠正能力由 GRW-003、GRW-004 描述。

**明确规则与异常：**

- 概览区展示日记数量和记忆锚点数量两个维度。
- 日记数量与个人空间、成长入口共用统计来源，应保持一致。统计的正式定义由 Q-005 确认。
- 锚点数使用当前设备可访问的成功锚点读模型总数：每篇日记当前版本最多一条，加上成功的每日聊天总结批次；不计失败/跳过任务、隐藏旧版本或纠正记录。加载失败时不回退原型示例数字。
- 当前入口未指定标签时进入 GRW-003 的全部锚点集合，按展示日期倒序；成长树主题入口仍按所选分类过滤。
- 聊天日总结仅作为可见锚点，不注入后续聊天上下文；用户纠正同样只改变锚点展示。
- 锚点和纠正按设备隔离并随来源记录存续，不跨设备同步，不独立于来源保留。

**验收条件：**

- **PET-002-AC01：**萌宠页展示小橘形象、日记数量和当前身份真实锚点数量；锚点数由统一读模型计算，空数据为 0，读取失败不显示示例数字。日记统计仍遵守 Q-005。
- **PET-002-AC02：**点击「记忆锚点」后打开全部锚点；列表可以按日期分页读取日记锚点与聊天锚点。
- **PET-002-AC03：**在同一数据状态下，萌宠页与个人空间、成长入口展示的日记数量一致。

**源码证据：**[概览和锚点入口](../../../../app/(tabs)/pet.tsx#L35)；[共享统计函数](../../../../src/store/diary-domain.ts#L33)；[默认锚点分类](../../../../app/profile/anchors.tsx#L35)。

**待确认问题：**Q-005 日记统计口径仍未确认；锚点不注入聊天上下文，摘要/纠正的来源留存范围已在 GRW-003/004 明确为随来源记录存续。
