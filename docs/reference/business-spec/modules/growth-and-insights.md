# 个人空间与成长洞察

版本：FSD v0.1 · 原型能力基线初稿。范围：个人空间、成长树、记忆锚点、锚点纠正、记忆花朵、里程碑及专属洞察报告。月度装订由 DIA-007 描述，不在本模块重复定义。

本文将原型表达的成长记忆视为产品业务能力。【交互已表达】表示可以在原型中完成操作；【展示已表达】表示已有展示意图；【预告未开放】表示入口或文案表达了未来能力。示例统计和固定素材不作为正式业务算法；没有确定的算法保留为待确认问题。

## 用户路径

底部导航「我的」 → 「我的小世界」查看回忆，或「小橘眼中的你」查看成长树 → 标签查看锚点 → 阅读关联日记 / 纠正理解。成长树 → 记忆花朵 → 查看里程碑与解锁进度 → 满足条件后阅读专属洞察报告。

## 功能规格

### GRW-001 个人空间与统计

**证据状态：**【交互已表达】进入回忆、成长记忆和月度装订；【展示已表达】头像、昵称、简介、VIP 标识、通知 / 设置图标及日记积累数量。

**业务目标：**为用户提供个人记录资产的集中入口，并呈现记录积累与成长记忆。

**前置与流程结果：**

1. 用户进入「我的」，看到个人资料和日记积累数量。
2. 点击「我的小世界」进入回忆归档。
3. 点击「小橘眼中的你」进入 GRW-002；月度装订入口进入 DIA-007。

**明确规则与异常：**

- 「我的小世界」展示已积累记录数量，并与 PET-002、成长入口使用同一日记统计来源。
- 原型统计使用示例基线加本次会话新增记录，不能把固定数量或计算方式直接认定为正式统计口径。
- 头像、昵称、简介、VIP 标识及通知 / 设置图标表达资料与身份展示意图；原型没有表达账号编辑、会员购买、通知或设置的操作流程。正式范围由 Q-012 确认。
- 当前成长入口的锚点数和开花进度文案为示例展示，正式统计与成长规则由 Q-005、Q-006 确认。

**验收条件：**

- **GRW-001-AC01：**个人空间显示头像、昵称、简介以及记录积累维度；不将示例昵称、VIP 状态或固定计数作为所有用户的固定断言。
- **GRW-001-AC02：**点击「我的小世界」后进入回忆页；点击「小橘眼中的你」后进入成长树页。
- **GRW-001-AC03：**点击月度装订的「查看全部」或某一本月份书籍后，进入月度装订流程；合集行为按 DIA-007 验收。
- **GRW-001-AC04：**同一数据状态下，个人空间、萌宠页及成长入口展示的日记数量一致。

**源码证据：**[个人空间与入口](../../../../app/(tabs)/profile.tsx#L12)；[成长入口卡片](../../../../src/components/profile/growth-entry-card.tsx#L4)；[统计来源](../../../../src/store/diary-domain.ts#L33)。

**待确认问题：**Q-005 记录数量、照片数量、记录天数及同行者统计口径；Q-012 账号、VIP、通知与设置范围；Q-001 资料和记录的数据归属 / 持久化。

### GRW-002 成长树与标签

**证据状态：**【交互已表达】标签和花朵入口；【展示已表达】成长树、记忆标签、日记 / 锚点概览及成长进度文案。

**业务目标：**把小橘对用户日记的长期理解组织成可探索的主题记忆，提供从主题到具体回忆的路径。

**前置与流程结果：**

1. 用户从个人空间进入「小橘眼中的你」。
2. 用户点击成长树上的主题标签，进入该标签的锚点页 GRW-003。
3. 用户点击花朵、主题花朵文案或成长提示，进入 GRW-005。

**明确规则与异常：**

- 当前原型展示「珍视旧友」「追光的人」「山与海」「深夜食堂」四类主题标签；标签与具体日记的关联由 GRW-003 描述。
- 「人生旷野的寻路者」花朵主题以及花朵图形属于记忆花朵入口。
- 返回操作返回上一页；无可返回页面时进入「我的」。
- 日记统计与其他概览保持一致；锚点计数和「再长若干片叶子会开花」表达成长意图，不定义正式阈值。
- 自动生成标签、叶子增长、花朵产生及标签更新没有可确认的业务算法，见 Q-006、Q-016。

**验收条件：**

- **GRW-002-AC01：**成长树页显示当前原型的四类主题标签；点击任一标签后打开对应分类的锚点页，页面标题反映该标签。
- **GRW-002-AC02：**点击树上的花朵、花朵主题文案或成长提示后进入记忆花朵页。
- **GRW-002-AC03：**页面展示日记 / 记忆锚点两个统计维度与成长提示；该条件只验证展示，不验证自动长叶或开花。
- **GRW-002-AC04：**返回动作在有历史页面时返回上一页，在无历史页面时进入「我的」。

**源码证据：**[成长树页面](../../../../app/profile/insights.tsx#L14)；[标签与花朵交互](../../../../src/components/profile/growth-artwork.tsx#L17)；[标签素材元数据](../../../../src/components/profile/growth-assets.json#L23)。

**待确认问题：**Q-006 标签、叶子、花朵之间的成长算法与进度展示；Q-016 标签 / 锚点提取、日记修改后的更新；Q-005 锚点统计口径。

### GRW-003 锚点阅读与原日记关联

**证据状态：**【交互已表达】按标签打开锚点、阅读关联日记；【展示已表达】从原日记提取的短摘、日记日期、标题及封面。

**业务目标：**让用户看见小橘从新保存日记和宠物聊天中记住的内容，并能追溯到原始记录。

**前置与流程结果：**

1. 用户新保存日记或小橘聊天后，服务端只处理本次新增来源；日记编辑仅刷新该篇当前版本，不重新处理其它日记。
2. 新日记每个当前版本最多生成一条摘要，完整读取有效正文/引用段落并保存所有来源段落 ID。无可总结正文时跳过，不生成虚构锚点。
3. 聊天只处理功能启用后的完整问答，按设备当地日期分组；新一天首次完成聊天时，异步总结此前未处理的完整问答。多日积压合并为一条补记锚点，日期显示实际生成日；无新增聊天不触发模型调用。
4. 摘要由服务端现有小橘文本模型生成，日记摘要与聊天摘要均为不超过 60 字的一句话，并只能归入最接近的现有主题。聊天摘要从小橘视角表述；对用户经历、感受和偏好的陈述必须有用户发言依据。
5. 用户从成长树按主题浏览，或从 PET-002 打开全部锚点并按日期混排。日记卡片打开来源日记；聊天卡片打开对应宠物聊天并定位来源消息。
6. 用户可纠正任一来源锚点。纠正只替换卡片显示，最多 240 字；不改原始日记/聊天，不进入模型上下文，也不传给后续提取。日记新版本不继承旧版本纠正。

**明确规则与异常：**

- 日记锚点卡片展示来源日记的发布时间、标题、封面和模型摘要；聊天锚点展示摘要生成日与「小橘的陪伴记忆」来源标题，并可追溯到组成该摘要的全部来源消息。
- 四类主题规则：`friends` 珍视旧友关系与共同回忆；`light` 个人成长、希望与目标；`mountains` 旅行、自然与探索；`food` 饮食、餐桌与食物相关时刻。主题只从四类中选最接近的一类，不创建动态主题。
- 新日记/更新日记和聊天总结使用同一服务端模型配置，但使用独立的记忆总结提示词；不传历史日记、已总结聊天、照片、EXIF 或聊天上下文以外的用户资料。
- 多来源聊天批次在来源消息或设备身份不可访问时不展示；日记必须仍是锚点绑定的当前版本且所有来源段落可读。
- 从萌宠页未指定主题时展示全部有效锚点，按展示日期倒序；成长树点击主题时仍只读该主题。缺省和未知标签均按全部集合处理。
- 有用户保存的纠正时优先展示纠正并标识「已按你的想法更新」；无纠正时展示原模型摘要。
- 锚点数据和纠正按设备隔离并随来源记录存续；不跨设备同步、不承诺独立于来源的留存。模型失败最多尝试 3 次（总次数，间隔 3 秒）；最终失败只记录后台状态，不显示假锚点或手动重试入口。

**验收条件：**

- **GRW-003-AC01：**已保存的新日记当前版本至多有一条真实模型摘要锚点；摘要只引用该日记有效正文/引用段落并保留所有来源 block ID。无有效正文时跳过且不调用模型。
- **GRW-003-AC02：**已更新的一篇日记只更新自身当前版本锚点；不重新总结其它日记，旧版本锚点/纠正不在当前列表显示。
- **GRW-003-AC03：**新保存锚点从模型选择四类之一，摘要为一句不超过 60 字的中文；模型未配置或失败时不产生 mock/固定样例锚点。
- **GRW-003-AC04：**点击日记来源卡片打开对应日记；点击聊天来源卡片打开来源聊天并定位到来源消息，不跨设备读取。
- **GRW-003-AC05：**有已保存纠正时卡片直接显示纠正文案及更新标识；无纠正时显示原摘要。纠正最多 240 字且不修改来源原文。
- **GRW-003-AC06：**从萌宠页进入默认查看全部有效锚点并按展示日期倒序；成长树主题入口只显示所选主题，空集合显示真实空态。
- **GRW-003-AC07：**同一设备当地日期的新增完整聊天仅被处理一次；新一天首次完成聊天时触发，多个未处理日期合并成一条、卡片日期为生成日；不含上线前旧 turn、失败/未完成 turn；同一批次重放不重复创建。
- **GRW-003-AC08：**来源和提取按设备身份隔离；更改/删除来源后失效锚点不展示，纠正不转移到来源新版本，也不注入聊天上下文。

**源码证据：**[标签关联与短摘](../../../../app/profile/anchors.tsx#L14)；[分类选择与关联日记](../../../../app/profile/anchors.tsx#L35)；[卡片与空状态](../../../../app/profile/anchors.tsx#L60)。

**待确认问题：**锚点触发、标签、来源、数量、纠正作用、日记更新和设备留存的本模块决定已由本版本明确；Q-002 的完整 AI 质量评分仍未闭环，Q-005 中日记数量等统计口径继续单独管理。

### GRW-004 锚点纠正

**证据状态：**【交互已表达】打开纠正面板、编辑、保存、取消及更新展示。

**业务目标：**允许用户纠正小橘对一段回忆的理解，使用户对自己的记忆含义保持控制。

**前置与流程结果：**

1. 用户点击锚点卡片的更多动作，打开该锚点的「说说你的理解」面板。
2. 面板以已保存的纠正内容或当前短摘作为初始值。
3. 用户修改后保存，面板关闭，卡片显示新的理解；取消则不保存此次编辑。

**明确规则与异常：**

- 页面底部「它可能看错了？点我纠正」打开当前分类第一条可用锚点的纠正面板。
- 非空内容才能保存；保存前去除首尾空白。
- 纠正内容为非空文字，去除首尾空白后最多 240 个 Unicode 字符；服务端也执行相同边界校验。
- 日记与聊天锚点均可纠正。纠正只更新锚点卡片显示并保留更新标识，不修改来源正文/消息，不影响其它锚点、后续提取、小橘聊天或洞察报告。
- 纠正按设备与锚点来源版本持久保存；来源日记更新后不转移旧纠正，来源记录不可访问时纠正不再展示。
- 点击取消、遮罩或系统关闭动作关闭面板；无锚点时不显示底部纠正动作。

**验收条件：**

- **GRW-004-AC01：**从某张卡片打开纠正面板后，输入初始值与该卡片当前理解一致；从底部纠正入口打开时，目标为当前分类第一条可用锚点。
- **GRW-004-AC02：**输入空字符串或仅空白时，保存按钮不可提交；输入非空内容可保存。
- **GRW-004-AC03：**保存后面板关闭，目标卡片显示去除首尾空白的纠正文案及更新标识；再次打开面板时以保存内容作为初始值。
- **GRW-004-AC04：**修改后取消或关闭面板，原先显示的理解不变；保存纠正不改变关联日记正文。
- **GRW-004-AC05：**当前分类没有锚点时，不显示底部纠正入口。

**源码证据：**[编辑初始值](../../../../app/profile/anchors.tsx#L43)；[卡片和底部纠正入口](../../../../app/profile/anchors.tsx#L73)；[输入、保存及取消](../../../../app/profile/anchors.tsx#L84)；[纠正状态保存](../../../../src/store/use-app-store.ts#L201)。

**待确认问题：**来源记录永久删除后的物理清理/审计保留和跨设备恢复属于 Q-001 全局留存范围，当前不做跨设备同步或独立留存承诺。

### GRW-005 记忆花朵与里程碑

**证据状态：**【交互已表达】查看花朵页、点击报告入口查看解锁条件；【展示已表达】花朵主题、锁定 / 绽放状态、成长里程碑和报告解锁进度。三类花朵的日记 AI 识别和报告解锁规则已按本节确认并开始实施；叶子成长规则仍未定义。

**业务目标：**用花朵和里程碑呈现用户的记录成长，并说明专属洞察报告的解锁条件。

**前置与流程结果：**

1. 用户从成长树进入记忆花朵页，查看主题、里程碑和解锁进度。
2. 未解锁时点击报告入口，收到条件提示并留在花朵页。
3. 已解锁状态下点击报告入口，进入 GRW-006。

**明确规则与异常：**

- 文案明确表达「集满 3 朵花可解锁专属洞察报告」。
- 固定花朵主题为「人生旷野的寻路者」「觉察自我的思考者」「压力迷茫的疗愈者」；服务端模型仅按有效日记正文/引用中的明确证据识别这些类别，为每类生成最多 60 字的说明并记录来源日记 ID/版本。模型不能新建主题、不能做临床诊断，证据不足时不授予对应花朵。
- 首次进入花朵页时，自动对当前设备全部可访问的已保存日记做一次 baseline 识别；之后新保存/编辑只分析本篇当前版本。无有效正文不调用模型；任务按设备持久化、幂等和可恢复。每类最多授予一次，已授予花朵不因来源编辑/删除撤销；三类全部授予后由服务端授权报告。
- 模型只读取服务端日记 text/quote 正文；不读普通聊天、锚点纠正、照片、EXIF 或用户资料。模型调用使用宠物聊天的服务端 `PET_CHAT_*` 配置，但使用独立提示词、不复用聊天上下文或 SSE。
- 里程碑展示首次旅行、连续记录 30 天、100 个锚点，只显示进度，不直接授予花朵或解锁报告。首次旅行由模型依据日记证据识别；30 天按设备日历日去重，只显示最新连续记录段，日期中断后从 1 重新累计；100 锚点使用当前设备有效日记/聊天锚点总数。
- 新日记保存时服务端记录设备当地日期，编辑保留首发日期；历史日记缺少当地日期时依次使用持久发布日期、入库时间，均无有效时间才不计入连续天数，不使用当前时钟伪造历史记录。
- 自动模型批次仅尝试一次；失败明确显示并允许用户手动重试，不回退 mock。未解锁时点击报告入口解释条件并留在当前页；已解锁后进入报告。
- 花朵、识别任务、来源引用和报告按设备身份持久化；不跨设备同步。报告模型运行在服务端，页面需说明处理及留存范围，不能再声称数据只保存在本地。
- 返回操作在有历史时返回上一页，无历史时进入成长树。

**验收条件：**

- **GRW-005-AC01：**花朵页展示花朵主题、成长里程碑、解锁条件及进度区域；不以固定示例进度断言所有用户的状态。
- **GRW-005-AC02：**未获花的类别显示真实锁定状态，点击报告入口显示集齐三类花的条件并留在花朵页；无服务端状态或服务失败时不伪造固定初始进度。
- **GRW-005-AC03：**服务端持久状态中的三类花全部获授后，逐朵显示绽放、模型说明和来源；报告入口可用并进入 GRW-006。
- **GRW-005-AC04：**锁定与解锁状态的进度展示、按钮语义及报告访问结果一致。
- **GRW-005-AC05：**首次访问只启动一次全量日记识别；后续每篇新建/编辑只处理自身版本；同类花不会重复授予或被迟到结果覆盖。
- **GRW-005-AC06：**首次旅行、连续 30 天最新连续段和 100 锚点进度使用真实来源；无日期历史行优先回退入库时间，无有效时间不参与连续段。
- **GRW-005-AC07：**无来源、不完整/越权模型结果和 Provider 失败均不得授花或解锁；每次失败只尝试一次，用户手动重试后才重新提交请求。

当前实现仍需验证真实模型识别质量及设备页面；叶子如何获得不在本次决议范围。

### GRW-006 专属洞察报告

**证据状态：**【交互已表达】锁定校验、返回花朵页和已解锁报告阅读；【展示已表达】基于用户记录的洞察标题、来源数量及三类个人洞察。服务端结构化生成、来源版本和页面状态接线已实现待最终验收。

**业务目标：**在成长条件达成后，把长期记录组织为可阅读的个人洞察，帮助用户回看自己的偏好与特质。

**前置与流程结果：**

1. 用户在已解锁状态下从花朵页进入报告。
2. 报告展示记录来源数量与洞察内容。
3. 未解锁状态直接进入报告时，展示锁定说明，并提供返回花朵页的动作。

**明确规则与异常：**

- 报告页和服务端 API 均校验三类花是否由该设备真实获授；不能仅依赖入口页或客户端 `flowerUnlocked` / 路由参数拦截。未解锁时不返回报告正文、不启动模型。
- 未解锁时展示「再等一朵花盛开」及集满 3 朵记忆花的条件，不展示已解锁报告内容。
- 已解锁后，用户进入报告页时服务端按当前设备全部有效日记 text/quote 来源版本生成或读取报告；报告固定为内在矛盾、珍视之物、性格特质三个维度，输出保留来源日记 ID/版本。
- 首次报告按需生成；源日记新增/编辑/删除后将当前结果视为过期，下一次进入报告页才更新。更新中保留上次成功报告；失败保留旧报告并提供手动重试，不自动重试或回退 mock。
- 报告来源数量是本次实际纳入模型的有效日记数，不声称等于 Q-005 全局个人统计；模型结论必须能关联输入来源，证据不足时说明不足，不诊断或定义用户。
- 报告以「这不是定义，只是一面镜子」表达辅助自我回看的定位。
- 报告、任务和来源版本按设备身份在服务端持久保存，不跨设备同步；页面说明应准确表述服务端模型处理及设备隔离，不得写“数据仅保存在本地”。

**验收条件：**

- **GRW-006-AC01：**未解锁状态直接打开报告时，显示锁定说明和花朵入口，不显示三类洞察正文。
- **GRW-006-AC02：**点击锁定页的「去看看记忆花朵」后进入花朵页。
- **GRW-006-AC03：**由服务端模型基于当前设备有效日记正文/引用生成并持久化三类洞察及来源版本；结构错误、未解锁或无来源不得显示为成功报告。
- **GRW-006-AC04：**显示本报告实际有效来源日记数量、生成时间、设备隔离处理说明及「这不是定义，只是一面镜子」定位。
- **GRW-006-AC05：**未解锁直达页面/API 不读取或生成报告；授权必须由服务端三花记录验证。
- **GRW-006-AC06：**源版本变化后打开页面按需生成新报告；生成中/失败时保留上次成功版本，只有用户显式重试才再次调用。
- **GRW-006-AC07：**报告来源仅限当前设备全部有效日记正文/引用，不包含普通聊天、锚点纠正、照片、EXIF 或跨设备数据。
