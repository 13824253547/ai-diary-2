# 橙光 AI 日记业务与功能规格说明书

版本：v0.2 · 2026-10-13 · 原型能力基线初稿，待业务确认。

## 文档定位

这套文档把当前前端原型表达的能力视为真实业务，回答“产品有哪些业务、用户怎样使用、每项功能应产生什么结果”。它为后续需求确认、开发拆分、验收、测试用例生成提供共同依据。

最合适的专业名称是 **业务与功能规格说明书（Functional Specification Document，FSD）**。PRD（产品需求文档）通常还包含目标用户、产品目标、优先级和版本规划；本次是从已有原型反向梳理，尚不能替代完整 PRD。业务确认某个版本后，这套说明可成为 **需求基线**；配套的 **需求追踪矩阵（Requirements Traceability Matrix，RTM）** 连接需求、验收标准、开发任务、测试和缺陷。

当前源码仍为 iOS 优先、仅本地 mock 的前端原型。文档中的“生成”“导出”“陪伴”等描述的是业务能力，不代表真实服务、文件落盘或第三方接口已经接入。展示意图和未明确规则会单独注明。

## 业务总览

产品的核心业务链是：**将照片整理成可编辑的 AI 日记，收藏和回看生活，再通过分享、陪伴和成长洞察延伸这些记忆的价值。**

| 业务板块 | 用户目标 | 当前原型表达的功能 | 规格入口 |
| --- | --- | --- | --- |
| AI 日记创作 | 从照片开始写一篇日记 | 相册授权、选照片、旅行类型、排版师、生成进度、人物命名 | [创作](modules/diary-creation.md) |
| 日记与回忆管理 | 修改、收藏和找回日记 | 阅读、编辑、局部重写、照片引用、更换风格、草稿保存/放弃、日期检索、月度装订 | [日记管理](modules/diary-management.md) |
| 隐私与分享 | 决定哪些内容给谁看 | 四种公开范围、选段公开、匿名处理、海报预览、平台分享、长图/PDF | [隐私与分享](modules/sharing-and-privacy.md) |
| 素材与灵感 | 收集照片、装饰和写作素材 | 添加/搜索/预览照片、用于日记、贴纸/印章、灵感卡、AI 补图 | [素材库](modules/material-library.md) |
| 明信片 | 把一个瞬间做成卡片 | 预设照片、照片素材和装饰应用、生成、分享与保存 | [明信片](modules/postcards.md) |
| AI 萌宠陪伴 | 与小橘交流生活与心情 | 文字对话、陪伴记忆概览、锚点入口 | [陪伴](modules/companion.md) |
| 发现社区 | 阅读他人的故事并互动 | 推荐/同城/最新、搜索、故事详情、点赞/取消 | [发现](modules/discovery.md) |
| 个人成长与洞察 | 从长期记录中认识自己 | 个人空间、统计、成长树、记忆锚点和纠正、花朵/里程碑、专属报告 | [成长与洞察](modules/growth-and-insights.md) |

首页是这些业务的工作台，底部“首页、回忆、萌宠、发现、我的”是导航组织。一个业务可跨多个页面，一页也可承载多个业务，因此功能规格按业务划分，页面另建索引。例如“匿名公开”同时影响正文、姓名、照片、摘要、海报和导出。

## 范围与证据口径

| 标记 | 含义 | 如何用于开发和测试 |
| --- | --- | --- |
| 交互已表达 | 原型有输入、动作、状态变化或结果 | 可形成初始功能验收条件；仍需确认正式产品规则 |
| 展示已表达 | 有内容、文案或结果示例，完整规则尚未给出 | 验收已表达的展示/锁定行为；算法与交付规则先确认 |
| 预告未开放 | 明确提示未来能力，当前入口不可使用 | 当前只验收不可用状态；不纳入已开放业务流程 |

这三个标记说明证据程度，不是后端完成度或发布状态。文中的 AC 是可审阅的初始验收标准；文件导出、渠道交付等同时给出假定真实能力后的业务目标，并注明当前原型只能核验的部分。有问题编号的部分需先确认问题，不能把源码里的缺口直接冻结成产品需求，也不能用预览反馈代替真实业务交付。

明确开放的创作类型是旅行游记。工作反思、情绪记录的创建入口为预告；已有情绪类示例日记可阅读，与开放情绪创作是两件不同的事。人物、照片和社区内容是示例集合；47 篇日记、128 张照片、固定日期、台南地点等属于演示数据，不作为用户配额或业务常量。

VIP 标识、通知图标、设置图标没有对应完整业务。风险支持提示页存在，但自动检测和触发链路尚未表达。账号登录、付费、评论发布、关注、日记删除等没有足够证据纳入当前已表达功能。

## 编号与版本规则

功能 ID 使用模块前缀，例如 `CRE-002`；验收条件使用 `CRE-002-AC01`；用例使用 `TC-CRE-002-001`。页面改名或功能移动时保留 ID。一条功能可以有多条验收条件，一条验收条件可以有多个边界、异常或自动化用例。

先确认范围和 [待确认问题](open-questions.md)，再为开发版本标记“已确认”和优先级。后续规则变化应修改对应规格、记录原因及日期，并在追踪矩阵标记需要调整的用例。初稿不擅自分配负责人、排期或产品优先级。
