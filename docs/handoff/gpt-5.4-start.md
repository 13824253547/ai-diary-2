## 可直接用于 goal 的提示词

```text

一、事实来源与基线

严格只以当前仓库为准，先 git status，保留所有既有未提交修改、删除和新增文件，不覆盖、不回滚、不清理无关工作。
新轮开始读取 AGENTS.md、delivery/README.md、execution-context.md、
decision-register.md、coverage.md、development-strategy.md、external-dependencies.md，
以及 reports/development-progress.md、autonomous-progress.md、
autonomous-acceptance-matrix.md、autonomous-blockers.md、current-execution-snapshot.md。
同轮连续推进只核对发生变化的基线及当前任务，避免反复读取不变文档或重复跑相同测试。
每项开发先读对应 task、同名 CASE、契约、源码、配置及既有测试。确认路径和符号存在；
区分需求、实现、mock 占位和验证证据，旧摘要/记忆/预期结果不得覆盖当前事实。
旧提示词与当前已批准策略冲突时，以本提示词和 development-strategy.md 为准。

二、开发轮：推进全部可开发部分

按 README 和每份 task 的真实依赖建立拓扑顺序，严格不越过前置能力。在依赖已满足的可执行任务中，标记 `S/M/L` 复杂度并按简单到困难推进：`S` 为局部、少层次且不需 schema/外部接入的改动；`M` 为多层接线或有明确状态/并发边界的改动；`L` 为跨域持久化、安全/隐私、平台/供应商或高不确定性工作。复杂度只安排先后，不改变验收要求和业务重要性；当前候选及分类理由同步写入开发台账。
先完成依赖就绪的简单任务，再处理中等、困难任务；依赖未满足的任务单独登记，不得为了易做而破坏业务链。不要因 CRE-005、DIA-005、DIA-006 的验收或产品决策未闭环停留在同一模块；没有独立开发缺口或达到返工上限时，登记后跳过受影响分支，继续其他已就绪项。
开发领域模型、服务、仓库、持久化、权限/归属、输入校验、状态机、
请求/版本/幂等/并发/取消/错误恢复和既有入口的业务接线。
“已编写”“开发完成待测”“已有实现待复验”不等于通过验收。
缺少测试/截图/设备实证本身不是业务代码的开发阻塞。

三、外部能力：先业务、后真实接入

按 external-dependencies.md 分类，不能将所有 HTTP 请求都视为第三方。
真正需要模型服务的日记生成、局部重写、宠物聊天、AI 配图、洞察报告，
以及方案待定的锚点提取：先开发应用自己的业务和服务契约，缺供应商/凭据时
使用同接口、可替换的 mock/deterministic adapter；仅延期真实适配器与质量评测。
宠物聊天先实现会话、消息、请求关联、归属、留存和失败恢复，回复由 mock provider 占位；
禁止仅硬编码页面回复或仅改提示文案就称业务开发完成。
平台专属分享缺 SDK/注册/审核时，先开发资产和交付编排；外部交付占位不能写真实成功记录。
相册、系统权限、图片/PDF/明信片渲染、已知框匿名遮挡和系统分享可用框架/库开发；
自有社区查询/阅读/点赞后端也可开发，不因真实外部条件不足整项跳过。
mock 放在服务/adapter/provider 边界，显式标记来源、隔离数据和身份，
不得混入生产或真实交付记录，真实服务失败不能静默回退为 mock 成功。
保留已接通的真实保存/查询服务，不因本轮 mock 授权擅自替换它们。
未经授权不得调用收费供应商、上传用户数据、安装大模型或做生产部署。
新的第三方需求先登记能力、影响任务、接入缺口和恢复动作，不猜供应商或凭据。

四、产品决策、UI/UX 与资源安全

产品 Q 尚未确认时，明确规则和无争议工程部分先开发，受影响分支登记并跳过。
建议默认值不得冒充已确认规则；仅对工程常规选择自主决定。
本次调整只授权开发节奏和缺失外部能力的 mock，不自动授权改变正式 UI/UX。
禁止改变样式、布局、文案层级、按钮状态、反馈、路由或用户路径；
禁止新增验证开关、调试参数、隐藏按钮。既有 PCD-001 暂停决定仍保留。
若必须改变正式可见行为，准确列出授权边界并暂停该接线，其他服务层工作继续。
权限/设备/凭据/外部服务缺失先登记 blocker，暂停受影响部分，不反复执行必然失败操作。
CRE-002 仅在轮次启动或相关实现变动时核对代码、既有测试记录和 iOS blocker；
DEV 轮无相关改动时不反复执行 14 项回归或重试 E_NO_PERMISSIONS。
数据安全不能 mock 绕过。清表/reset/覆盖/迁移/外部调用前确认影响；
测试用明确隔离临时库，禁止在有用户数据的开发库执行 reset，凭据不打印。

五、开发轮完成与集中测试

DEV 轮不要求每完成一项立即新增/运行测试，不反复跑全量 Jest/e2e、截图和设备验收。
保留既有测试；可做必要类型/编译/静态检查和最小安全验证，未运行就明确“未测试”。
全部 42 项形成有源码依据的开发结论，且无独立可开发遗漏后，汇总待测清单进入 TEST 轮。
结论区分：本轮实现完成待测试、mock 业务完成待真实接入、已有实现待复验、
外部适配器延期、产品/UI/环境阻塞。未盘点/实施中不能算完成。
外部延期不等于整体开发完成；TEST 轮可先验本地范围，真实外部 CASE 保留延期。
TEST 轮统一按 task/CASE 执行单元、领域、契约、隔离集成、设备/文件/端到端及 AI 质量验证。
失败如实记录 CASE、输入、环境、预期/实际、证据、严重度与影响，
集中形成下一 DEV 轮缺陷清单并修复，随后集中复测，禁止删除或弱化断言伪造通过。
每项任务初次开发不计返工；此后最多进行两轮缺陷修复，每轮均须复测。第二轮修复后的复测仍未通过时，标记“达到返工上限，暂跳”，记录未解决 CASE/缺陷和恢复条件，停止当前任务缺陷线并继续其他依赖就绪的任务。暂跳不是通过、关闭或从原始范围移除；不得在新会话中重置该任务计数。
一次返工轮是针对一轮集中测试发现的问题所做的一批合并修复；无代码变化的重跑不算新返工轮，但不得重复运行已知必然失败的检查。设备/凭据/外部能力/Q 决策缺失导致不能验证时记为对应阻塞，不消耗缺陷返工次数。数据损坏、越权、隐私泄漏等严重问题仍须立即停止危险操作并优先处理，不能以次数上限为由遗留不安全实现。
越权、隐私泄漏、数据损坏等危险问题立即停相关测试、优先修复，不等本轮结束。
已有但中断/未验证的测试实现留在待测清单，不引用更早的绿灯证明新代码通过。

开发阶段优先更新对应 task 的实现段及 reports/development-progress.md；
记录源码、mock/真实模式、依赖/复杂度、剩余缺口、待测 CASE、已用返工轮数与暂跳/恢复条件，并同步四份原台账中的阶段/实际变化。
CASE 和 acceptance matrix 只按实际证据修改结果，保留历史失败/通过，未测试不计通过。
分别报告开发进度和验收进度，禁止用 225 条验收通过率代替开发工作量。
当前 42 项盘点已完成；后续每次以当前 worktree 重算任务主状态：实现完成待测、mock 业务完成待真实接入、已有实现待复验、延期/阻塞、实施中、达到返工上限暂跳。
开发盘点不完整时不猜开发百分比；盘点完整后也不以任务计数或验收率伪装全部交付。
验收进度按 coverage 的有效总数和矩阵明确 passed 项重算，partial/阻塞/待测不计。
开发轮验收百分比不增长是正常状态；汇报优先说明新增业务实现，而不是重复测试数。
每次汇报注明当前 DEV/TEST 轮次、增量实现、mock 范围、实际运行/未运行检查、
延期条件、需要用户处理的事项和下一步。
全局范围始终是原 delivery 全部要求。只有当前代码与真实证据证明所有原始要求均闭环，
且无延期/阻塞/未验证项时才标记 goal 完成；不得以 mock 业务或一轮开发结束替代最终成功。
```
