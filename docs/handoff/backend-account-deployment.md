# AI旅行日记后端部署

本程序面向用户名密码和邮箱验证的新账号版本。旧数据库、旧素材目录和旧 Docker 项目不读取、不迁移、不清理；新系统使用独立数据库和媒体目录。首次切换后，原先使用旧身份的客户端将不能继续使用原 API 身份。

## 部署命令

在项目根目录执行：

```bash
npm run deploy
```

该快捷命令使用本机 SSH 别名 `orange-glow-prod`，并直接确认线上部署。命令会在本机构建包含完整代码的 Linux/amd64 运行镜像和迁移镜像，上传并校验完整版本，初始化或复用新系统资源，检查新后端，再把现有 `/api/` 转发切到新后端。实际执行会影响线上 API，请先确认维护窗口。

需要自定义 SSH 目标时，使用 `DEPLOY_SSH_TARGET=你的SSH别名 npm run deploy:backend -- --confirm-live`；原 `deploy:backend` 命令没有 `--confirm-live` 时只显示帮助。快捷命令固定使用 `orange-glow-prod`，不读取自定义目标。

迁移镜像仅安装锁定版本的 Prisma CLI 和数据库 schema/迁移文件，不包含后端源码或全部开发依赖。部署前会检查该 CLI 与后端 Prisma 客户端和开发依赖的锁定版本一致；升级 Prisma 时需同步更新 `backend/deployment/migration/package.json` 和锁文件。

## 上传方式

- 每次构建并发布完整代码镜像，不在旧容器里局部覆盖代码。程序对依赖清单、锁文件、Dockerfile、`.dockerignore` 和实际基础/依赖镜像层计算指纹；已知依赖发生变化时上传完整镜像归档。
- 依赖未变且本机、服务器都安装了 `rsync` 时，程序复制上一版归档作为基底，仅传输归档差异，生成新的完整归档并验证 SHA-256。原归档不被覆盖，仍用于回滚；传输量取决于镜像内容变化。
- 对没有指纹的现有版本，会尝试核对服务器已有镜像的依赖层；无法确认、没有上一版归档或缺少 `rsync` 时安全回退为全量上传。Dockerfile 不再匹配已审查的镜像层布局时也强制全量上传，需重新审查布局后才能恢复差量传输。
- 终端显示部署阶段及上传进度；全量模式显示已发送的文件大小，差量模式使用 `rsync` 进度和统计。上传完成后仍须等待校验、数据库状态检查和服务启动，直到看到部署成功。

## 首次准备

- 快捷命令的 SSH 目标为 `orange-glow-prod`；原部署程序未配置目标时默认使用 `ubuntu@152.32.225.67`。服务器需为 Linux x86_64，已安装 Docker、Docker Compose 2.30 或更新版本、Python 3、Nginx 和 systemd。
- 使用 SSH 密钥或 SSH agent 实现免密登录，并确保账号可执行 `sudo -n`。SSH 严格校验已登记的服务器指纹；首次登记前应通过可信渠道核实指纹。
- 使用原 `deploy:backend` 命令时，可在被 Git 忽略的项目根目录 `.env.deploy.local` 中设置 `DEPLOY_SSH_TARGET=你的SSH别名` 或 `DEPLOY_SSH_TARGET=用户@主机`；环境变量同名设置优先。不要在该文件存放密码。
- `backend/.env` 必须提供真实 Ark 服务的 `PET_CHAT_PROVIDER`、`PET_CHAT_BASE_URL`、`PET_CHAT_MODEL`、`PET_CHAT_API_KEY`，以及 `SMTP_HOST`、`SMTP_PORT`、`SMTP_USER`、`SMTP_PASSWORD`、`SMTP_FROM`。SMTP 使用 SSL 465，发件人与账号必须一致；其他 AI 图片、超时等可选参数也会同步。
- 本机需安装项目依赖、Docker Buildx，并能构建 `linux/amd64` 镜像。服务器需有足够磁盘和内存容纳其他服务、新 MySQL 和新后端；程序检查镜像上传和加载所需磁盘，但按用户要求不设固定可用内存门槛。服务器约 1 GiB 内存且无 swap，内存不足可能触发 OOM 并影响其他项目，需在部署和业务负载下持续监控；程序不会自动停止其他服务。
- 服务器需要能获取 `mysql:8.4` 镜像，或已在本地缓存该镜像；部署程序上传的是后端运行和迁移镜像。
- 服务器现有 `/etc/nginx/orange-glow.locations.conf` 必须包含唯一的 `/api/` 路由，且该路由的 `proxy_pass` 为 `127.0.0.1:3001` 或新服务的 `127.0.0.1:3002`；不符合时程序拒绝自动修改。

## 隔离资源

- 新目录：`/opt/orange-glow-account`；新 Docker 项目：`orange-glow-account`。
- 新 MySQL：仅监听 `127.0.0.1:33308`，库名 `orange_account`，数据位于 `shared/mysql-data`。
- 新后端：仅监听 `127.0.0.1:3002`；素材与临时文件分别位于 `shared/photo-assets`、`shared/generation-tmp`。当前后端运行路径不依赖 Redis。
- 首次部署生成独立 MySQL 密码和账号签名密钥，保存在服务器 `shared/*.env`，权限 `0600`。后续部署保留这些密钥，更新本地指定的 AI/SMTP 配置。凭据经 SSH 标准输入传输，不放进镜像、命令参数或日志。
- 路由和已有新系统后端配置在修改前备份到本机 `~/.orange-glow-deploy/backups/<版本>/` 和服务器 `/opt/orange-glow-account/backups/<版本>/`，其中后端配置含密钥，须保持私有。完整镜像归档保存在各版本目录供回滚，注意磁盘占用。

## 迁移与回滚

- 首次初始化时先确认新数据库为空，再执行完整 Prisma 迁移。迁移里的旧表删除语句只作用于这个独立新库，不连接旧库。
- 后续部署先运行迁移状态检查。如果有待执行或失败的迁移，程序会停止，不自动修改已有新库。数据库迁移可能不可逆；应先评估兼容性、备份并单独确认迁移和恢复方案，不能把旧镜像回退误当成数据库回退。
- 若新后端启动或 Nginx 切换失败，程序尝试恢复先前 Nginx 配置、后端环境和上一版完整镜像；新库和媒体不回滚、不删除。首次部署失败时停止新后端并保留新库供排查。
- 如果初始迁移中断，`shared/migration.inprogress` 会阻止自动重试，需先人工核查新库状态。残留 `.deploy.lock` 也需要确认没有部署进程后再处理。
- 如果回滚本身失败，程序会明确报告；应检查本地/服务器备份、容器状态与 Nginx 日志，不要删除数据卷或执行 `down -v`。

## 验证边界

程序的健康检查仅验证新后端 HTTP 可启动，不代表注册、真实邮箱收件、iPhone 交互或 AI 服务已经验收。线上隐私政策不会由此程序更新；发布账号和邮箱验证前还需同步真实隐私披露。

用户于 2026-11-19 手动部署版本 `r20261119095429-326e3b68`，独立数据库与后端容器健康，线上健康接口返回 200、未登录账号接口返回 401。真实账号流程、邮件送达、真机交互和负载峰值仍未验收。

本地 `npm audit --omit=dev` 报告 6 项高危、1 项中危依赖问题，其中包括 `multer` 和 `body-parser` 拒绝服务漏洞；上述数量是受影响包数量，不等于独立漏洞数量。上线前应评估并修复依赖风险，Prisma 的部分修复涉及大版本升级，不能直接假定兼容。
